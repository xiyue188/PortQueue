## 批次顺序与范围

执行顺序：**4A—4D → 5A—5D → 3D1—3D3 → 6A—6C → 7A—7E**。3D是预约遗留闭环，放在队列及计划成熟后处理关联影响；7D按基础对象拆批，不与统计一次交付。每次只推进一个批次，开工时在对应条目补足文件、接口、测试数据及命令；不提前写全系统代码级方案。

每页按真实任务选主视图。共用到访身份、详情入口和反馈规则，不共用万能列表模板。操作后更新相关模块；例如离锚影响队列、实际待办和总览，计划确认影响排期、队列预计安排和到访详情。未打开页面标记数据过期，进入后重读，不为同步而请求所有页面。

## 阶段5：泊位计划与资源排期

2026-11-28用户认可[HTML交互原型](design/berth-prototype/index.html)，本批补齐5A真实资源、版本、实际占用及到访往返。正式Vue泊位页已开放四角色读取，保持“泊位为行、时间为横轴、到访为时间条”的构图；待安排/全部到访提供真实总量、搜索及分页。已完成计划可按历史日期回查，未离泊占用独立于计划结束时间。实施及验证见[本阶段记录](stages/stage-5-implementation.md)。下一批仅推进5B草稿编制与真实拖动保存，再依次5C确认、5D调整；原型可拖动不等于正式写入已交付。

人工预计是可空的候泊参考；计划靠泊来自有效确认版本。有确认计划时优先显示计划，人工预计按需展开；二者不复制、不强制同时填写，人工预计也不是可用时段查询的最早靠泊限制。该呈现规则先在5A原型验证，随后接入时统一锚地与泊位详情。

5A验收前明确以下六点：①从锚地选船进入后保留同一次到访及返回位置，其余泊位计划仍可见；②日期切换、横向浏览、定位当前时间和点击时间条可用，24/48小时及跨日比例正确；③未安排、草稿、已确认、执行中、已完成以文字及线形分清，草稿不占正式窗口；④空泊位、船型不符、时段冲突、实际超时有具体对象与时间，不能仅标红；⑤桌面100%缩放、1366×768和390px均能阅读，窄屏可切明细；⑥原型操作明确是预览，5B前不写正式库。每个批次仍分别设计、实现、review、验收与提交。

接入前核查两项数据库前提：现有计划过程只核验启用账号/角色，5B—5D开放写接口前须补ADMIN/DISPATCHER权限及越权回归；计划取消、候选版本与已执行基准在5D明确，不能让取消后的队列仍显示有效安排。样例已有确认计划只证明数据库能力与第四阶段读取，不计为第五阶段页面交付。

| 批次 | 输入 → 处理 → 输出；前后端与SQL职责 | 完成本批的证据 |
|---|---|---|
| 5A 资源、版本与实际占用查询 | 日期/区间、所选到访 → 查询本港全部资源、当前/候选版本和事件实际占用 → 时间轴、完整到访清单、版本详情和跨页定位；读取SQL及列权限同步补齐 | 四角色可读、匿名拒绝；完整总量/分页/字面搜索；跨日、已完成历史、未离泊与靠泊前日期；选船不隐藏其余计划；查询中断/失败/身份变化与关联写入失效；桌面/短屏/窄屏 |
| 5B 编制与拖动草稿 | 选择待安排到访，在可用资源上选区间/拖动 → 显示旧新泊位和时间，表单精调 → 保存草稿版本并读回 | 拖动吸附默认15分钟而精调到分钟；点击不改变原有精确时间；取消不写库；同内容保存不产生无意义版本；响应未知先核对，不重复建计划；草稿冲突提示不冒充正式占用 |
| 5C 确认与并发冲突 | 草稿版本/确认动作 → 事务检查船型、尺度、吃水、吨位、设施状态和时间窗 → 正式安排、队列安排状态和审计 | 重叠拒绝、相接允许；两个会话确认同一冲突窗口最多一个成功；返回实际状态；失败原安排不变；3个业务视图与页面一致 |
| 5D 调整版本、延期与取消 | 拖动未执行计划提出候选安排，或表单调整允许字段/取消未执行计划 → 受控版本或取消事务 → 新当前安排、释放窗口、影响提示和历史 | 候选未确认时不替换原安排；执行中只按规则调整计划离泊，不换已靠泊泊位/靠泊事实；取消同步队列安排语义；保持恰好一个当前版本；不得自动推移后船 |

拖动只是输入方式，点击表单能完成同一业务。15分钟不是数据库约束。首批不做边缘缩放和批量自动排程；泊位、起止时间、冲突和影响必须可读，不能靠颜色猜。5D确认调整不改写实际执行前的历史基准。

## 预约补充3D：关闭关联缺口

| 批次及依赖 | 本批范围 | 验收标准 |
|---|---|---|
| 3D1 驳回后重新申报；沿用3A—3C | 设计并实现受控修改/重新提交，完整保留原申请与审核快照；核对“每次到访唯一预约”的模型后明确状态迁移，不为复用表单伪造另一次到访 | 原驳回原因、内容及责任人可查；重申须再次审核；旧批准信息不能混入新判断；不能直接UPDATE绕过流程 |
| 3D2 预约撤销；依赖4C、5D | 对允许撤销且未实际进港的预约，统一处理预约终止、有效队列退出、未执行计划取消和窗口释放；实际在场保留至离锚 | 全部联动同一受控事务，任一步失败整体回滚；取消但在场仍可离锚；不删除历史；重复撤销可核对且不重复审计 |
| 3D3 已批准条件变更重审；依赖5D、3D2 | 对未执行申请的关键条件变更明确重审状态、原安排暂停/失效规则；重新批准后按新条件确认适用计划 | 变更后至重审和新安排确认完成前，不能执行旧批准和旧计划；当时申报与各次审核可追溯；取消/变更不留下占用或可执行的过期安排 |

3D开工先设计SQL约束、过程和审计快照，再接API和表单；不新增菜单、不绕开21个基本关系。执行后的事实差错归6C处理，不能冒用“申请变更”追改实际记录。

## 阶段6：实际作业与到访时间线

| 批次 | 输入 → 处理 → 输出 | 验收标准 |
|---|---|---|
| 6A 待办与完整时间线 | 角色/下一动作/所选到访 → 查询适用计划、实际记录与可办理条件 → 待办主视图和可展开时间线，补全4B建立的详情契约 | 从预约、队列、计划都定位到同一次到访；无锚地的直进路径也完整；计划/实际/审计时间分明；时间线不能通过动画假装事件已发生 |
| 6B 进港、靠泊、离泊 | 下一可登记动作及实际时间 → 既有事务过程重验前序、计划、权限 → 事件及唯一分类关联、状态结束和审计 | 锚地路径含实际离锚；直接进港无需锚地；重复事件、时间倒置、过期基准、越权均失败；离泊完成不冒称港界离港；各页及时更新 |
| 6C 时间更正与延误影响 | 选定错误事实、正确时间和原因 → 先设计受控更正事务和历史保留，再实现权限与时间链校验 → 可追溯更正、受影响计划及重算结果 | 不开放普通表UPDATE；保留前后值、操作者、原因；与前后事件、实际占用及执行基准矛盾时拒绝；延误提示后续安排而不自动改期；统计按明确更正规则重算 |

6C是正式功能报告中的必要能力；现有不可变事实保护与“受控更正”需先统一设计，未完成不能标为整套系统交付。变更不得消除既有审计或重新解释原执行版本。

## 阶段7：统计、基础维护与最终交付

| 批次 | 范围 | 验收标准 |
|---|---|---|
| 7A 口径和查询 | 按日期、船舶、泊位、预约状态定义等待、使用次数/占用、偏差与准点的单位、分母、归组日及执行基准；先给可手工核对的小样本SQL | 已完成等待与正在等待分开；多次锚泊能核对分段与累计；观察区间截断；近7日/30日无多一天；无样本不补0 |
| 7B 等待与泊位可视化 | 先完成等待趋势和泊位使用比较，图表选择联查明细；使用ECharts按需加载 | 同一筛选下图、表、SQL样本一致；0与无数据可区分；键盘可查；返回图表保留筛选；局部失败有恢复 |
| 7C 偏差、准点与导出 | 增加执行偏差分布/样本及准点摘要；CSV友好导出当前范围，实际需求明确后再决定是否增加xlsx | 采用实际执行前最后确认的适用版本；延期不洗掉历史偏差；导出与页面同口径、不截取当前页冒充全量；处理中文、逗号、换行和公式注入 |

| 7D2 港口与设施维护 | 港口、锚地、码头、泊位及支持船型；变更在用设施前检查影响 | 新旧候选与资源图同步；历史引用保留；不能停用后仍给新安排；缩减容量/能力不静默破坏已有记录 |
| 7D3 字典与账号维护 | 既有单角色模型、受控账号操作、船型等基础字典 | 管理员权限重验；旧会话失效；保护最后可用管理员；状态代码属于程序与数据库契约，不能随意添加状态绕过CHECK；历史类型/代码不重解释 |
| 7E 整套系统验收与材料 | 按统一验收计划复现完整到访、异常路径、角色切换、恢复与原生数据库取证 | 必需项均有执行结果；报告、页面、SQL与截图一致；独立环境可启动；材料沿同一次到访讲清输入、安排、事实和统计 |

## 固定工作顺序

1. 明确该批任务、输入输出、页面草图、数据库规则、复用候选和验收案例；对已确认偏好不重复提问。
2. 先改必要SQL与业务设计，再实现一条API和界面链路；注释解释模块职责与关键不变量。
3. 用真实应用数据库权限验证正常、失败、并发和未知结果；执行相关构建、自动化测试、SQL检查。
4. 以实际角色完成浏览器任务，保存100%缩放桌面/短屏/窄屏证据；检查可读性、交互、错误恢复和跨页一致性。
5. 深度review并修复阻断问题，结论写入 `docs/reviews/`；区分代码、API、浏览器与视觉验收，未执行就注明。
6. 精确选择本批文件，中文小步提交；推送前核对待推提交范围，避免夹带其他阶段成果。停止本批启动的服务，不影响用户原有进程。

文档优先更新执行计划、统一验收和现有设计记录；代码级细节随开工批次补全。当前完成5A真实查询与跨页联动；5B须先补写过程角色与请求/版本核对，再接草稿表单、拖动和按作业时长查找窗口。不能把原型交互或已有底层过程计为5B—5D正式交付。
