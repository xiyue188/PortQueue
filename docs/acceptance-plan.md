# PortQueue 最终验收计划

更新：2026-11-27。本文定义整套系统的完成标准；各项尚须按[阶段计划](stage-plans.md)实施和执行，不能把本清单当作通过记录。已有中期结果见[中期交付](stages/midterm-delivery-guide.md)及历史review。设计依据见[后续模块设计](design/post-midterm-direction.md)。

## 1. 验收对象与环境

Windows、VS Code、.NET 8、SQL Server Developer/Express（本机可用LocalDB）、仓库指定Node/pnpm版本。数据库验证使用独立测试库和应用最小权限身份，不能只在数据库所有者账号下通过。浏览器使用真实API，失败不回退Mock；管理员、调度员、审核员、记录员分别验证。基础样本可复现，用户原开发库记录不用于破坏性测试。

代码/构建、数据库/HTTP、浏览器任务、视觉效果分别记录结果。每个用例保存输入、前置数据、使用角色、关键主键、操作前后结果和实际执行状态；失败和未执行都不能计为通过。

## 3. 业务剧本

| 编号 | 实际操作 | 通过条件 |
|---|---|---|
| E01 锚地完整路径 | 调度员登记提交 → 审核员批准 → 入锚 → 查看/调序 → 确认泊位 → 实际离锚 → 记录进港、靠泊、离泊 → 统计回查 | 全程定位同一次到访；各次写入有正确关联和审计；全部页面及数据库结果一致；各段等待可核算 |
| E02 直接进港 | 已批准申请直接确认泊位，再记录进港、靠泊、离泊 | 无虚构锚地记录；时间线自然呈现直进路径，统计不把缺失锚泊误判为异常 |
| E03 驳回与重申 | 驳回并留原因 → 修改/重新申报 → 再审核 | 原审核和申请快照可查，不伪造第二次到访绕过唯一预约关系；新审批责任完整 |
| E04 撤销但仍在场 | 有锚泊及未执行计划的预约撤销 → 查询队列、容量、泊位 → 登记离锚 | 退出有效队列并释放计划窗口，仍计实际在场；真实离锚后才移除在场；其他写入被正确限制；失败整体回滚 |
| E05 获批条件变更 | 已批准并有安排的申请变更关键条件 → 尝试执行旧安排 → 重新审核并确认新安排 | 旧安排不能执行；审批和安排均按新条件验证；历史与原始内容保留；明确处理原窗口，不留下悬空占用 |
| E06 时间窗与适配 | 确认10:00—12:00，再尝试11:00—13:00；改为12:00—14:00；另测船型/尺度/吃水/吨位不适配 | 重叠拒绝、相接允许、不适配拒绝；跨日同样有效；草稿可见但不误算已确认占用 |
| E07 版本与取消 | 调整已确认计划，分别制造冲突/合法候选，确认后取消未执行安排；靠泊后再调整允许的计划离泊 | 失败不替换原安排；历史版本保留，当前版本不变量成立；取消释放窗口；历史靠泊偏差仍使用执行前适用版本 |
| E08 实际事实与更正 | 重复入锚/进港/靠泊/离泊、倒置时间；随后按原因更正合法误录时间 | 非法操作无残留；更正保留原值和责任人，影响前后事件/占用时先校验；图表按规定重算；离泊不等同港界离港 |
| E09 并发和未知结果 | 两会话调序/确认冲突窗口；写入成功后丢弃响应、再次核对；期间换账号或权限失效 | 队列不覆盖旧快照；冲突窗口最多一方成功；不重复版本/事件；服务端身份重验；保存成功但刷新失败有正确恢复 |
| E10 基础资料 | 新增船/设施供业务选择，停用已有引用资料，修改在用资源能力；尝试非法字典和重复候选键 | 历史引用不损坏，新业务限制生效；变更影响明确；非SHIP_TYPE或停用船型不可新引用；状态代码不能随意扩展 |
| E11 时间与指标 | 多次锚泊、跨零点/跨日、无样本、真零值、未结束在泊、执行后延期；使用固定小样本手算 | UTC存储/UTC+8展示一致；近7天/30天范围精确；当前等待与完成等待分开；分母不含未来；图、表、导出能逐条复核 |

## 4. 角色与交互验收

角色验收分别覆盖浏览器、HTTP和数据库边界。目标矩阵：ADMIN具备管理及授权业务操作；DISPATCHER负责登记、队列和计划；REVIEWER负责审核；实际入离锚、进港、靠离泊允许ADMIN、DISPATCHER、RECORDER办理。现有部分过程只检查账号及角色启用，须先补齐细分授权再通过验收；更正与维护另核对应权限。无权角色即使手工构造请求也必须失败，操作者不能由客户端冒充；匿名只读范围保持显式，不把维护或审计数据默认公开。

| 编号 | 场景 | 可观察的通过条件 |
|---|---|---|
| U01 连续办理 | 总览 → 预约 → 队列 → 排期 → 实际记录 → 统计 → 原记录 | 同船不同到访不混淆；明确下一步；返回保留筛选/选择/滚动；选船不暗中过滤全清单；未发生步骤不补造事实 |
| U02 锚地拖动 | 第5位拖至第2位，原位放回、取消、原因空缺、越权、并发、过滤/分页 | 预览顺移正确；确认才写入并留全量调整记录；原位/取消无写入；隐藏队列成员时不能错误重排；键盘/按钮可完成同一操作 |
| U03 泊位拖动 | 横向移时间、纵向换泊位、非法落点、非整刻度原计划、冲突、取消、执行中调整 | 时间比例真实，预览旧新差异；默认吸附不篡改原时间，表单可精调；已确认改动生成候选版本；不移动实际事实、不自动挤走后船；等价表单完整可用 |
| U04 数据同步 | 保存后换页、后台返回、账号切换、拖动期间轮询、503及迟到响应 | 有效缓存可复用，相关变化重读；拖动目标不被轮询挪走；旧响应不覆盖新意图；错误结果不可继续写入；账号切换清除无效待提交动作 |
| U05 图表联查 | 点击图段/时间点/样本，清除筛选，再导出 | 筛选可见且可取消；图和明细范围一致；键盘可查；无样本与0值区分；错误不画成0 |
| U06 视觉与趣味反馈 | 正常/空/加载/错误/无权限及长文本；鼠标、键盘、触摸 | 主任务突出，文字可读，错误能恢复；轻量小船、让位、吸附只反馈事实；无重复小字/调试标签，无整页闪烁；持续动效可暂停并尊重减少动态效果 |

视觉在100%缩放下检查1366×768、1440×900、1920×1080及390×844，并补320px窄屏边界。允许任务需要的滚动；禁止靠90%缩放、缩小正文或裁掉主操作假装一屏装完。外框统一，内部主视图按任务变化。拖动专用把手不抢占触摸滚动；正常滚动、键盘焦点、弹层取消和返回路径都须验证。

真实角色初次进入突出其任务；用户已设置的条件不被角色默认反复重置。至少一次由非开发讲解者按可见界面完成主要任务，记录卡住的位置；无此试用证据就注明未做，不能声称易用性已全面验证。

## 5. 数据库、恢复与材料证据

- 答辩前在独立排练库完成数据整理：不同锚地使用不同负载，包含超过五艘长队列、撤销仍在场、历史停留及可继续办理的获批预约；逐条核对申请、审核、预计、计划、实际与审计时间。不把各锚地固定五艘当作数据规模，不删除开发库历史来恢复截图。合成标识和设施规模有来源说明，不冒充真实运营数据。
- 从独立空库按文档恢复21个基本关系、3个业务视图、约束、触发器、过程、索引和样本；新增写操作可增受控过程，不把旧过程数量永久当目标。重复装载样本不产生重复业务记录，负向测试回滚无残留。
- 使用应用最小权限身份执行全部新增查询和过程，证明授权足够且不能直接改业务表；未知SQL错误不直接暴露给页面。
- 原生数据库工具截图必须包括实际对象树/表设计、主外键与结构、实际数据结果、3个视图及业务结果、关键事务过程、触发器、索引和审计查询。说明图不能替代这些原始截图。
- 用同一条E01到访串联页面截图、HTTP结果和SQL证据，额外用E02说明直接进港，用E06/E09说明约束与事务价值。证据记录当时主键与查询范围，不硬编码全库总量；报告可解释每一张图的输入、结果及来源。
- 在普通VS Code终端验证恢复、前后端启动和停止，记录端口/PID，交付前只停止本批启动的进程。环境配置示例无个人凭据，保留用户已有服务及开发数据。
- 在典型数据与扩充样本下测首屏、筛选、图表、长队列拖动和排期滚动，记录数据量、设备和实际耗时；发现瓶颈再优化查询/索引/绘制，不预设虚假的性能数字或引入企业压测平台。
- 最终报告、源代码、数据库脚本、样本、验收结果、截图及答辩材料一致。材料以已完成成果和一次到访为主，不出现内部阶段口号，也不把规划、同学原版或移动实验当主线成果。

## 6. 防止重复返工

下列共因随负责批次加入针对性回归，不另建庞大框架：选择误作过滤（4B）；页面缓存失效/503残留（4B、6A）；最低权限读不到数据（各新查询）；日期多一天（7A）；固定伪状态/版本重复（5B—5D）；短窗口裁切（各界面）；拖动和刷新竞态、鼠标有功能而键盘无功能（4D、5B/5D）；取消与变更未同步下游（3D）；导出与图表口径不同（7C）。

最终完成需E01—E11及U01—U06的适用检查全部有通过证据，空库恢复和材料核对完成，阻断问题关闭。每批review简记“问题、原因、修复、证据、未完成项”；构建成功、测试数量多或页面能查询均不能单独替代交付验收。
