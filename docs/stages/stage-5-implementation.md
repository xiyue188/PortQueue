# 第五阶段真实接入与逐批验收

2026-11-28。用户认可5A HTML方向，授权顺序完成5A→5B→5C→5D。每批独立验证、review和中文提交；不把后续实际事件登记页面提前混入。本文件仅记录本阶段执行，当前进度入口仍为stage-plans。

## 5A：资源、版本、实际占用和到访往返

- `GET /api/berths/schedule?from=&to=`：限最长48小时，返回本港全部资源、区间相关当前版本/最新未确认候选、区间实际占用和未离泊记录。日期带时区，ID按字符串传输。草稿/候选不计正式窗口，停用设施仍可查看历史。
- `GET /api/berths/visits?scope=waiting|all&keyword=&page=&pageSize=`：待安排是APPROVED且无计划或计划仍DRAFT的到访，不限三艘，不按入锚与否排除直进；默认有分页/真实总量，全部到访可追溯历史。取消计划不自动重建。
- `GET /api/berths/visits/{appointmentId}`：所选到访独立读取，包含当前/全部历史版本、实际事件、当前或最近锚地停留及人工预计。选择不筛掉资源图；预约/锚地/泊位往返保留查询和选择。
- 四角色可读，匿名401；查询失败清除失效数据，切页取消旧请求，身份变化清空。正式接入先仅开放查看，不混入原型假操作。
- 验收：最小数据库权限；超过一页候选/关键词字面匹配；跨日、相接、空资源、当前与候选、执行版本与延期版本、未离泊跨日期；三个入口对象一致且返回不重置；桌面/短屏/窄屏截图。

## 5B：草稿编制

先补数据库受控写入口和ADMIN/DISPATCHER权限，再接API与原型表单/拖动。新计划保持一个当前草稿；更新草稿产生新版本，未变内容不重复建版本。客户端发送请求键和已读版本，事务核对并发、预约/资源资格和时间；超时先核对原请求，不重放。冲突显示具体对象，草稿不冒充正式占用。

下一批具体设计：保存请求包含到访、泊位、带时区起止时间、原因、稳定请求键，以及已读取的当前/最新版本ID。SQL在既有`PortQueue.Schedule`事务锁内核验本港、ADMIN/DISPATCHER、预约资格和两份版本基准；任何一份变化均返回冲突，保留用户输入供核对。请求键、规范化内容摘要及原结果随版本审计保存，相同请求核对原结果，异内容/异操作者不得复用；不增加第22张表。成功结果在COMMIT之后返回。已确认计划的调整入口留到5D，5B只开放无计划和DRAFT。

前端沿用原型的条身/把手拖动及分钟表单，落点先预览，再确认保存草稿；独立显示旧、新泊位和时段。按所选船作业时长查找窗口时同时检查真实资源与实际占用，不把人工预计当作最早可安排时间。身份变化丢弃未提交办理状态；本页保存后刷新排期/到访，锚地和总览仅失效关联缓存。

验收：跨角色403与数据库拒绝；分钟精调、拖动15分钟、取消无写入；重复请求同结果/异内容冲突；两会话旧草稿不能覆盖；失败无计划/版本/审计残留；成功但刷新失败不重复提交。

## 5C：确认与并发

确认绑定计划、待确认版本和已读当前版本；共享排期事务锁，核对设施状态、船型/尺度/吃水/吨位、时间重叠及实际占用。相接允许，重复确认读取已生效结果，过期候选不得覆盖新安排。确认同事务更新当前版本、计划状态、有效锚地队列ASSIGNED及审计。

验收：同一冲突窗口两个会话最多一方成功；失败原版本继续生效；页面、3个视图和审计一致；执行/完成只由实际事件推进，不由时钟推进。

## 5D：调整、延期与取消

已确认计划横/纵拖动只生成候选，确认前旧安排不变。执行中只允许表单调整计划离泊，不移动泊位、不改计划靠泊和既有实际事件引用；实际基准仍是执行事件引用的版本。取消仅允许未执行DRAFT/CONFIRMED，填写原因，计划取消/有效队列回到WAITING/审计同事务；不删除版本，不移动其他船。

验收：候选/旧确认并存、旧候选不能恢复；延期与后船冲突拒绝；实际超时不显示空闲；取消释放正式窗口但实际在场仍保留；取消重复核对、越权/执行后取消拒绝；入口及总览局部刷新、到访时间线与审计可追溯。
