## 图一的三个数字

| 指标 | SQL 来源与口径 | 对应问题 |
|---|---|---|
| 待审核预约 | arrival_appointment 中状态 PENDING 的数量 | 有多少已提交申请尚未处理 |
| 锚地在场 | v_anchorage_queue 中入锚时间非空、离锚时间为空的停留记录数 | 当前记录上有多少次锚地停留尚未结束 |
| 待靠泊计划 | v_current_berth_plan 中 CONFIRMED 的当前计划数量 | 有多少已确认安排尚未开始执行 |

来源是 `database/queries/overview.sql`，经 Dapper 和 `/api/overview` 返回页面。三个数字分别观察申请、等待、安排三个环节，不是今日量、涨幅或船舶总数，不能相加。当前开发库查询为10、10、4；数值是本次快照，不能写死到代码。

在场数包含分配了泊位但尚未离锚的停留，不只统计WAITING。待靠泊计划不是空闲泊位数量，也不是所有已批准预约。由于后续业务页面尚未开放，这两项目前主要反映已装载场景；新建预约不会凭空产生入锚或已确认计划。

## 数据可以在页面新增

预约可新增，步骤：左下角登录 → 选择调度员（或管理员），初始密码123456 → 进港预约 → 清单右上“登记预约” → 选择已有船舶，填写未来申请到离港、作业时长及吃水 → 保存草稿或提交审核。保存草稿使草稿数量增加；直接提交使待审核增加。审核通过后待审核减少、已批准增加；重新打开页面仍保留数据。

未登录、审核员或记录员没有登记按钮。船舶、船公司、锚地、码头、泊位等基础资料暂无维护页，仍由受控数据库资料脚本维护；这是基础资料维护尚未接入，不是预约数据只能由后台增加。
