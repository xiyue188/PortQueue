# 阶段 3B：预约审核与演示可用性

日期：2026-11-09。状态：实现与验收完成。用户本轮授权先修复演示登录、图文层次，再完成审核闭环；3C 登记提交不在本轮。

## 实施顺序

1. 修复登录输入错误被显示为服务故障的问题。提供管理员、调度员、审核员、记录员四个真实账号选项，公开初始密码 `123456`。仅 Development 且显式启用时提供快捷选项与账号初始化命令；保留真实 Cookie、密码哈希与后端角色验证，不覆盖已有个人账号或自动重置密码。
2. 总览保留冰蓝外框、图像和全港口径；六状态增加比例图形，作业概要使用队列分段图、计划状态及实际事件柱形，零值/缺失不能冒充进度。提高正文/字段字号与标题层次；港口动态保持既有行为。
3. 将用户认可的船舶场景、状态与办理进度用于预约详情；草稿、待审、获批、完成的路径由状态驱动，驳回/撤销明确中止，不推算航行进度。不增加总览单船轮播。
4. 完整审核详情包括船舶/公司/船型、尺寸与最大吃水、到访计划、前后港、货物、申请时间、作业时长、申报吃水、优先级、危险品、特殊要求和审核事实。
5. 复用 usp_review_appointment，增加 ADMIN/REVIEWER 数据库授权与锁内复核；API 从会话取审核人，拒绝客户端额外操作者字段。审批输入仅决定和意见；驳回原因必填。并发/重复由事务状态检查保障。
6. 前端确认框绑定具体预约，提交中禁止重发。成功后保留本条最新详情并更新清单/总览；刷新失败明确保存结果，不提示再次审核。超时先查询状态，不自动重放写入。

| 编号 | 用例 | 必须结果 |
