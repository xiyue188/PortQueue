# 阶段 3C：预约登记、草稿维护与提交

> 2026-11-10 范围更新：本文保留 3C 当时实现记录；三个后续通用查询页及专用 API 已按用户要求撤下。当前只开放总览与进港预约，主图入口保留并提示待接入。最新范围见 [中期交付说明](midterm-delivery-guide.md)。

本批次承接 3B 审核，完成调度员登记到审核员处理的真实业务闭环。开发前确定以下设计与验收条件。

## 实施边界

- 总览保留冰蓝商务外框，图形采用明亮蓝色；主图显示配置港口的真实名称、代码与已登记设施数量。作业概要用可切换的横向数量图组织，明确当前队列、当前计划和累计事件三种口径。
- 四个业务入口对应进港预约、锚地排队、泊位计划、进出港记录。后三页查询既有三视图，提供分页与预约溯源，本批次不开放其写操作。
- 预约登记位于进港预约页，ADMIN、DISPATCHER 可用；REVIEWER、RECORDER 无登记权限。沿用 Cookie 与 CSRF，操作者来自会话。
- 新增一个受控事务过程，基本表仍为 21 张、业务视图仍为 3 个。新增过程负责 CREATE / EDIT / SUBMIT 三种命令；后端禁止直接写表。

## 写入规则

1. 创建到港航次和预约在同一事务内完成，分别追加审计；允许保存 DRAFT 或直接提交 PENDING。航次计划时间和申请时间分别维护。
2. 只编辑或提交 DRAFT。提交时重新验证启用船舶、启用 SHIP_TYPE、港口、时间、吃水、作业时长及值域。申请到港不能早于服务器当前时间。
3. 船舶与港口通过真实 API 搜索、分页选择；停用资料在历史详情可读，新登记不可选。
4. 新建请求携带 UUID，映射到唯一预约编号。创建审计保存原始规范化请求指纹和操作者；相同键与内容返回原结果，不新增业务或审计；内容或操作者不同返回 409。即使后来修改草稿，原请求仍可安全重放。
5. 草稿使用审计序号作为并发版本；编辑和提交在锁内核对，旧版本返回 409，不能覆盖其他窗口的修改。无须给原关系添加版本列。
6. 所有时间显式携带时区，存储为 UTC 秒精度；界面显示北京时间。小数不静默截断，数量、吃水、时长、优先级与长度在 API 和数据库共同校验。
7. 保存确认与随后读取分开。失败保留表单；响应丢失先核对结果，创建仅允许原键原内容重试，不生成新键导致重复预约。

## 验收矩阵

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| C01 | 调度员新建草稿 | 一条 PLANNED 航次、一条 DRAFT 预约、两条创建审计，无审核人 |
| C02 | 编辑并提交 | 详情字段一致；PENDING 与提交时间同时落库；审核员可承接批准/驳回 |
| C03 | 直接提交 | 单事务创建 PENDING；校验失败无残留航次、预约、审计 |
| C04 | 重复请求、响应丢失 | 相同创建键安全重放；不同内容 409；并发创建只有一份事实 |
| C05 | 旧版本/已提交记录 | 并发编辑只有一方成功；提交后修改草稿 409；重复提交不增审计 |
| C06 | 权限与伪造 | 未登录 401，错误角色 403，缺 CSRF/未知身份字段 400；数据库再次检查角色 |
| C07 | 输入边界 | 无效船型、停用船舶/港口、负值、过多小数、倒置时间、过期到港、超吃水/超时长均拒绝 |
| C08 | 回滚 | 注入审计故障后业务和审计均回滚；最小权限用户只能执行过程不能直接写表 |
| C09 | 总览与导航 | 明亮蓝图形、港口资料来自库；四入口能打开真实分页页面，返回后查询与选择保留 |
| C10 | 浏览器操作 | 真实登录→登记→编辑→提交→审核；表单错误可恢复；桌面和窄屏无横向溢出、可键盘操作 |
