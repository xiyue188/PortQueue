# 总览定位、场景数据与界面精炼

本轮以现有冰蓝风格为基础，完成用户明确提出的命名、冗余文案、主图与数据表现问题。先完成本批验收，再进入写功能和账号认证。

## 范围与设计

1. 首页改为“总览”，独立读取待审核预约数、锚地在场数、待靠泊计划数和近期事件；进港预约保持筛选、分页和详情。新增只读 `/api/overview`，查询基于已有基本表与三张业务视图，不新增数据库对象。
2. “实际执行”在界面称“进出港记录”，正式模型名称保持不变。去除重复副标题、课程/示意标签和更新时间页脚。时区继续统一 Asia/Shanghai，列标题按需保留 UTC+8。
3. 使用用户新提供的清晰船舶图做全局场景背景，不把它绑定为某艘实船照片；小图保持原素材。摘要只用一处克制波浪边，表格与字段区不变形。
4. 新增可重复执行的场景脚本：增加 48 条有不同船名、时刻、作业时长和六类状态的预约；已批准的记录中构造锚地等待及确认计划。数据为持久化合成场景，来源仅在文档解释。
5. 对原五条明确可识别的 PQ-DEMO 样例进行展示名称和业务编号升级，保留主键、外键、状态、事件和审核事实，不删历史；追加修改快照。旧种子脚本识别升级编号，避免重跑复制旧样例。未经修改识别匹配的用户记录不覆盖。
6. 账号区改为真实“未登录”状态，移除无功能下拉箭头。完整认证/角色授权沿用已有四类角色单独规划：管理员、调度员、审核员、记录员；在后端完成授权后才开放对应写入口。

## 验收

| 编号 | 标准 |
|---|---|
| R01 | 用户指定的冗余界面文字消失；必要字段、状态、错误恢复仍清楚 |
| R02 | 总览独立于预约筛选；三项指标与 SQL 查询一致，最近事件时间和类别可解释 |
| R03 | 新主图清晰无拉伸，移动端裁切可用，波浪边不影响数字/按钮可读性 |
| R04 | 48 条新增预约覆盖六种状态，申请时间不同；原五条不删除，重跑两次行数及审计数量不增长 |
| R05 | 已审核记录责任人与时间完整，已批准排队/计划可关联，状态不由前端随机生成 |
| R06 | 总览 API 通过真实数据库测试、最小读取权限和故障响应检查；原预约接口回归通过 |
| R07 | 浏览器验证两页定位、搜索/状态/分页、空/错误恢复和窄屏；构建与 SQL 静态检查通过 |
| R08 | 独立审查、设计文档、业务流程与权限阶段计划完成；中文分批提交 |

禁止通过前端替换查询字段、隐藏旧记录、伪造登录用户或放大统计值达成验收。
