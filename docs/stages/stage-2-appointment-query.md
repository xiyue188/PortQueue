## API 契约

`GET /api/appointments`，响应 `application/json`；查询无业务写操作。

| 参数 | 规则 |
|---|---|
| page | 默认 1，整数 1～1,000,000；超出结果页返回空 items 和真实 totalCount，不自动跳页 |
| pageSize | 默认 20，整数 1～100 |
| status | 可空；去首尾空格、转大写后允许 DRAFT、PENDING、APPROVED、REJECTED、CANCELLED、COMPLETED |
| keyword | 可空，去首尾空格后最多 100 个 UTF-16 单元；匹配预约编号、船名、IMO、MMSI；按字面包含匹配，%、_、[ 和转义字符不能充当通配符 |

固定按申请到港时间倒序、预约主键倒序；不开放任意排序字段。不限制当天，不混用申请时间、泊位计划时间和实际事件时间。关键词及状态之间取 AND，关键词各匹配字段之间取 OR。

成功结构：`{ items: [...], page, pageSize, totalCount }`。主键使用十进制字符串，防止 SQL bigint 超出 JavaScript 安全整数范围；计数和页码使用 JSON 数字。时间为 UTC ISO 8601（含零时区），页面固定以 Asia/Shanghai 显示。

| 响应字段 | 数据来源 | 说明 |
|---|---|---|
| appointmentId / appointmentNo | arrival_appointment | 主键字符串 / 业务编号 |
| shipName / imoNo / mmsi | ship，经 port_call 关联 | 以库中事实为准 |
| requestedArrivalAt / requestedDepartureAt | arrival_appointment | 申请到港 / 申请离港 |
| appointmentStatusCode | arrival_appointment | 六种状态之一 |
| reviewerName | user_account.display_name | LEFT JOIN；未审核为 null，不能漏掉待审核预约 |
| reviewedAt / reviewComment | arrival_appointment | 可空；页面以“—”表达无记录 |

查询源在 `database/queries/appointments.sql`，由基础设施项目嵌入资源加载。一次 SELECT 返回总数和当前页；用外连接保留空页的总数，配合数据库已有 READ_COMMITTED_SNAPSHOT，避免两次独立查询观察到不同提交状态。不存在船舶/到访孤儿记录由既有外键保证。

错误采用 ProblemDetails，含 HTTP status、中文 title、稳定 code、traceId；400 另含字段 errors。不返回 SQL、连接字符串或异常堆栈。参数错误为 400/INVALID_QUERY；可识别的数据库连接或超时故障为 503/DATABASE_UNAVAILABLE；其他内部故障为 500/INTERNAL_ERROR。数据库失败不能返回 200 空数组。

## 页面与请求状态

页面进入即查询全部预约。使用标题、筛选表单、结果表和分页，保留 PortQueue 名称与港口工作台语境，不增加指标卡、虚假实时状态或无功能按钮。旧总览仅作为明确标记的原型保留，不承担本次验收。

- 状态、关键词提交和页容量变化回到第一页；刷新使用已提交的筛选条件。
- 表单草稿与已提交查询分开，避免用户修改输入但未查询时，分页偷偷使用新条件。
- 新查询取消旧请求，并用请求序号防止迟到结果覆盖；退出页面清理请求。
- 加载时清除过期列表；空结果显示清除筛选入口；失败显示重试，禁止回退 Mock。
- 表格为真实 table，状态有文字说明；控件有 label、键盘焦点和禁用语义；窄屏表格仅在自身区域横向滚动。
- 使用 `/api` 相对路径，由 Vite 代理至本机 5180；本机开发和 preview 均可联调。部署同源代理另行配置，不开放任意来源 CORS。

## 验收矩阵

| 编号 | 场景 | 通过标准 |
|---|---|---|
| A01 | 全部记录与空审核信息 | 真实数据库返回样例；待审核不丢失，审核字段 null |
| A02 | 状态和关键词组合 | 六种状态按字面约束；编号、船名、IMO、MMSI 可查询；空白归一化 |
| A03 | 分页与并列时间 | 页之间不重复；固定主键次序；超出页保留总数；页容量上限生效 |
| A04 | 非法参数 | 0、负数、溢出、非整数、非法状态、过长关键词返回 400 和稳定 code |
| A05 | 特殊字符与注入 | 引号、%、_、[ 和反斜线按字面匹配，不扩大结果、不报 SQL 语法错误 |
| A06 | ID 与时区 | 超过 2^53 的 ID 精确作为字符串返回；时间明确为 UTC，页面显示北京时间 |
| A07 | 数据库故障 | 真实不可达 SQL 连接返回 503；无 SQL/凭据/堆栈；健康接口仍只代表进程存活 |
| A08 | 查询权限 | 完整查询可在 portqueue_probe 下执行；不扩大现有列授权 |
| A09 | 页面状态 | 真实数据、筛选、分页、刷新、空、失败与恢复可演示；无 Mock 兜底 |
| A10 | 隔离与回归 | 集成用例只创建和删除本次随机测试库；不清空 PortQueue；既有健康测试通过 |
| A11 | 界面与构建 | 桌面/窄屏可用，无页面横向溢出；前端类型检查、构建、SQL 静态检查通过 |

SQL 集成测试分类为 Database；默认完整测试需要 SQL Server，普通 HTTP 契约测试可单独运行。测试数据库名称由程序产生并校验，连接配置不得指定要删除的业务库。新鲜测试夹具验证 2 条 APPROVED、2 条 COMPLETED、1 条 PENDING 的 PQ-DEMO 基线，另加专用边界记录；不假设开发库永远停留在初始状态。
