# 阶段 2 界面对照改版计划与验收

日期：2026-11-07。范围：现有前端整体视觉和预约查询交互，后端 API 和数据库模型不扩展。

## 已确认的视觉约束

用户五张原图为已确认的设计方向，直接实现，不进行另选风格的提案。主参考为 overview-cargo：总览上方摘要、左宽右窄的船舶焦点/信息区、下方记录表；预约页采用横向船舶摘要、左列表与右详情。品牌改为 PortQueue，内容改为真实预约数据。

取样：海报外围 #4b4a50；侧栏中部约 #b5d1e6；工作区约 #b6d3e7；半透明面板约 #c8dceb。侧栏约占框宽 15%，主要区约占 85%；卡片间距 12–16px，圆角 12px，玻璃白边 1px，深蓝按钮与蓝色选中态。系统字体优先 Segoe UI / Microsoft YaHei，图标采用统一描边。

## 实施顺序

1. 规则和参考源归档，保存本计划。
2. 重做侧栏和顶部；总览改用真实预约结果；预约列表增加当前行选择与右侧详情，同一份查询状态贯通两个布局。
3. 以真实 API 验证筛选、分页、选中行、详情、刷新、空与错误恢复；截图对照桌面和窄屏。
4. 深度 review、修复、记录实际设计规范，小步中文提交。

## 业务适配边界

- 统计使用筛选后总数或当前页状态数量，标题明确口径；不复制参考中的 96%、航程、货物或文件数量。
- 船舶图仅为场景示意，详情中的名称/编号/时间/状态/审核数据来自真实 API。
- 侧栏保留 6 个业务位置：预约总览、进港预约、锚地排队、泊位计划、实际执行、查询统计；后四项标注待接入且不可提交虚假操作。
- 顶部参考动作适配为真实查询与刷新；不出现假通知、假登录人或无后端的新增预约按钮。
- 不保留旧版静态 Mock 总览。当前只读能力全部保留；无登录功能时底部显示本地演示身份说明。

## 验收标准

| 编号 | 标准 |
|---|---|
| U01 | 参考图的侧栏/顶栏/摘要/主次分栏/表格拓扑及冰蓝玻璃材质均可在桌面截图对照 |
| U02 | 原真实预约筛选、分页、重置、刷新和错误重试均保留 |
| U03 | 选中预约同时更新摘要、详情及总览焦点，不将不同记录字段混合 |
| U04 | 空结果和请求失败清除旧详情，不出现 Mock 或误导的过期数字 |
| U05 | 页容量或状态变化回到第一页；翻页使用已提交条件；迟到响应不能覆盖新请求 |
| U06 | 键盘可操作导航、筛选、行选择和分页，窄屏没有整页横向溢出 |
| U07 | 真实 Chromium/Edge 浏览器截图、控制台检查和交互测试；测试故障响应明确属于测试夹具 |
| U08 | 前端构建、相关测试、SQL 静态检查通过，review 记录来源及尚存边界 |

测试截图与报告进入忽略目录；参考原图和素材来源说明留在仓库。业务 API、21 表与 3 视图保持原有语义。
