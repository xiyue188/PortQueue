# 阶段 3：身份权限与预约登记、提交、审核

日期：2026-11-09。状态：**3A 已完成验收，3B/3C 尚未实施**。本批详细设计与验收见 [身份权限与总览职责收口](stage-3a-session-and-overview.md)。按 3A → 3B → 3C 逐批实施、验证、review 和提交。

## 1. 目标与页面位置

本阶段完成第一个真实写业务闭环：登录 → 登记/保存草稿 → 提交 → 查看完整申报资料 → 批准或驳回 → 查询结果与审计一致。业务操作集中在现有“进港预约”，总览继续显示汇总与动态，不增加顶层菜单。

| 位置 | 设计 |
|---|---|
| 左下账号区 | 提供登录；成功后由后端返回姓名、单一角色及可用操作，提供退出 |
| 预约清单工具区 | 有登记权限时显示“登记预约”；保留候选搜索、状态筛选和分页 |
| 预约详情 | 展示完整申报及审核事实；待审核且有权限时显示“批准”“驳回”；草稿且有权限时显示“编辑”“提交审核” |
| 登记/编辑抽屉 | 按船舶与到访、申请与作业、补充要求分组；桌面侧边抽屉、窄屏铺满，底部固定保存/提交操作 |
| 审核确认框 | 显示预约编号和船名，填写意见；驳回原因必填。提交中禁用重复操作，失败保留输入 |

沿用冰蓝商务风格、统一外框和主次栏。前端按真实状态与权限显示操作，后端负责授权，数据库负责事务与历史完整性。未实现按钮不提前占位。

## 2. 实施批次

| 批次 | 实现范围 | 结束时必须可演示 |
|---|---|---|
| 3A 身份与权限 | Cookie、标准密码哈希、账号启停、登录/退出、防伪造和登录限速；不开放预约写入 | 正确登录、错误拒绝、真实姓名/角色、退出和停用后失效；认证与授权测试通过 |
| 3B 预约审核 | 完整详情查询、审核过程授权、批准/驳回 API、确认框及局部刷新 | 对已有待审核预约完成审核；状态/责任人/时间/审计一致；越权、重复及并发审核得到正确结果 |
| 3C 登记与提交 | 基础资料候选、到访与预约事务创建、草稿编辑、提交、表单及失败恢复 | 新登记 → 保存草稿 → 修改 → 提交 → 审核；刷新或重启后数据仍在 |

先审核已有预约，是为了复用已验证的审核过程，先完成较小的写链路；最终演示仍按“登记 → 提交 → 审核”顺序。每批开工前补充实际变更文件及测试名称，验收通过才进入下一批。

本阶段不实现基础资料管理后台、多角色分配、第三方登录、实时 AIS 或自动调度。撤销涉及队列、计划和实际事件，留到关联业务接入时单列一致性用例，不做孤立的改状态按钮。已驳回记录保留事实，不改回草稿；重新申请建立新记录。

## 3. 身份与权限

沿用 `user_account.role_code` 的单角色模型和四类角色，不增加权限表。阶段 3 的权限如下；后续队列、计划、事件权限在对应阶段细化。

| 操作 | 未登录 | ADMIN 管理员 | DISPATCHER 调度员 | REVIEWER 审核员 | RECORDER 记录员 |
|---|---|---|---|---|---|
| 当前预约及总览只读 | 允许，保持现有本地展示边界 | 允许 | 允许 | 允许 | 允许 |
| 登记、编辑草稿、提交 | 拒绝 | 允许 | 允许 | 拒绝 | 拒绝 |
| 批准、驳回 | 拒绝 | 允许 | 拒绝 | 允许 | 拒绝 |

这是单港内部人员操作，无外部船代账号或“仅能修改本人申请”的规则，创建人通过审计追溯。管理员明确具有上表两类业务权限，演示用调度员和审核员两个真实账号分别操作。

采用 ASP.NET Core Cookie 和 PasswordHasher，不自制加密。现有 `password_hash varbinary(256)` 保存标准哈希编码的字节，3A 必须验证编码往返和长度，禁止截断。密码通过本机管理命令安全输入，不写 SQL、日志或仓库；已有场景操作人不自动变成可登录账号。

Cookie 设置 HttpOnly，生产 HTTPS 下设置 Secure；写请求验证防伪造令牌，退出清除 Cookie。每次认证请求复核账号与角色启用状态；停用或变更角色影响下一次请求，不能继续相信旧 Cookie 中的权限。后端从会话确定操作者，不接受前端指定审核人、创建人、审核时间或任意目标状态。API 策略和事务过程均校验操作角色。无需 JWT 刷新链、Redis、消息队列或独立认证服务。

## 4. 数据与事务

保持 21 个基本关系、3 个业务视图及原 E-R 语义，不增加业务表。复用到访、预约、账号、角色、船舶、字典、港口和审计关系。

| 操作 | 前置条件 | 同一事务内的动作 |
|---|---|---|
| 创建 | 有登记权限；船舶 ACTIVE，船型为启用 SHIP_TYPE；字段合法 | 生成 PLANNED 到访及 DRAFT 预约，记录二者审计；选择直接提交时同事务转为 PENDING、设置提交时间；全部成功才提交 |
| 编辑草稿 | 状态仍为 DRAFT | 更新允许修改的申报及到访字段并写前后快照；不能覆盖已提交或已审核事实 |
| 提交 | 状态仍为 DRAFT，重新检查时效、船舶/船型可用性 | DRAFT → PENDING，设置提交时间，追加审计 |
| 审核 | 有审核权限，状态仍为 PENDING | 复用 usp_review_appointment；转 APPROVED/REJECTED，记录会话操作者、数据库时间和前后审计 |

沿用当前事务锁和行状态检查，不引入分布式锁。并发审核最多一个成功；后发请求返回冲突并读取最新状态。写响应丢失时先查询确认结果，不盲目重放。登记请求需稳定请求标识，同一表单重试保持相同标识，通过编号唯一约束和事务去重只创建一次；3C 开工时在现有编号字段内确定编码方案，验证“相同标识/不同内容”冲突，不新增专门的幂等表。

### 表单与详情字段

审核详情必须读取完整资料，不能只凭当前列表中的船名、时间和状态审核。

| 字段组 | 输入与显示 | 规则 |
|---|---|---|
| 船舶 | 搜索/选择启用船舶；显示 IMO、MMSI、船型、船长、最大吃水和船公司 | 发送 shipId；写事务再次校验船舶和船型启用状态 |
| 到访 | 系统生成编号；计划到/离港、可空前一港/下一港、可空箱量/货重 | 写入 port_call；真实港口主键；非负整数箱量、非负两位小数货重 |
| 申请时间 | 申请到港、申请离港必填 | 离港晚于到港；提交时到港不得早于服务器当前时间；界面北京时间，传输带偏移，数据库 UTC |
| 作业与吃水 | 预计作业小时、申报吃水 | 正数、两位小数、符合现有 decimal(6,2)；吃水不超过船舶最大吃水，作业时长不超过申请时间窗 |
| 优先级与要求 | 1—5 级选择、危险品标志、特殊要求 | 优先级本阶段不触发自动调序；标志为布尔值，要求最多 1000 字，空白归为空 |
| 审核意见 | 决定与意见 | 驳回去除首尾空白后必填，最多 1000 字；审核人和时间由服务端提供 |

到访计划时间与申请时间是不同事实。登记可用申请值初始化到访计划值，但允许分别确认，修改申请时不能无条件覆盖计划。草稿允许时间已过以便修正，提交重新校验；历史已提交记录不因当前日期改变而失效。数字上限和精度以现有 SQL 类型为边界，API 返回字段错误，不静默截断或舍入。

## 5. 接口契约（3A 已实现，3B/3C 待实施）

| 批次 | 接口 | 输入 → 输出 |
|---|---|---|
| 3A | GET /api/session | 无业务参数 → 身份或 null、权限及防伪造令牌 |
| 3A | POST /api/session/login、/logout | 凭据/退出请求及防伪造令牌 → 设置或清除 Cookie |
| 3B | GET /api/appointments/{id} | 主键 → 完整申报、状态和审核事实 |
| 3B | POST /api/appointments/{id}/review | decision、reviewComment → 最新主键/编号/状态/审核事实 |
| 3C | GET /api/ships、GET /api/ports | 有界分页、关键词 → 可选资料；船舶只返回 ACTIVE 且船型启用项 |
| 3C | POST /api/appointments | 申报字段、草稿/提交意图、稳定请求标识 → 预约与到访编号、主键、状态 |
| 3C | PUT /api/appointments/{id}/draft | 完整草稿字段 → 更新后草稿；非草稿冲突 |
| 3C | POST /api/appointments/{id}/submit | 会话与主键 → PENDING 和提交时间 |

bigint 主键继续使用字符串。首次创建 201，其他成功 200；字段错误 400、未登录 401、越权 403、不存在 404、状态/重复内容冲突 409、限速 429、数据库不可用 503。错误沿用 ProblemDetails，给出稳定代码与中文说明，不暴露 SQL。创建去重重放返回已有结果。

写成功后重读详情并刷新清单、摘要和总览。若状态变更使记录离开当前筛选，清单按真实条件更新，详情仍显示本次结果并给出简短成功反馈；不能误切换到另一条记录让人以为操作对象错了。若写成功但读刷新失败，区分“保存成功”和“列表暂未刷新”，避免诱发重复提交。

## 6. 验收矩阵

| 编号 | 输入/动作 | 必须观察到的结果 | 证据 |
|---|---|---|---|
| A01 | 正确/错误密码、未知或锁定账号 | 正确登录，其余统一拒绝；密码/哈希不进入响应、日志和审计 | API 集成、日志检查 |
| A02 | 未登录、错误角色、伪造操作者写入 | 401/403；责任人不可由客户端覆盖；业务及审计无变化 | API/SQL 对照 |
| A03 | 退出、停用账号/角色、变更角色后再次请求 | 下一请求使用新授权，旧会话不能继续越权 | API 集成 |
| A04 | 缺失防伪造令牌、连续错误登录 | 拒绝/限速；正常同源流程可用，无明文凭据提交仓库 | API/浏览器 |
| R01 | 打开待审核详情 | 逐项完整申报与船舶资料，时间和精度正确 | 页面/API/SQL 对照 |
| R02 | 批准或有原因驳回 | 状态、责任人、数据库时间和一次审核审计一起提交 | 独立库/浏览器 |
| R03 | 空白驳回原因、无效决定、不存在主键 | 400/404，无状态或审计变化 | 负向测试 |
| R04 | 重复及两人并发审核 | 重复 409；并发恰好一个成功，只留一次审核更新审计 | 两个独立连接 |
| W01 | 合法登记存草稿/直接提交 | 到访、预约、审计一起创建；DRAFT 无提交时间，PENDING 有 | 独立库/浏览器 |
| W02 | 非法时间/精度/范围、超吃水、停用船舶/船型 | 清楚的字段错误、创建无残留；选择候选后停用也被拒绝 | API/数据库 |
| W03 | 草稿保存、修改、提交，再编辑/提交 | 草稿可修正；提交后拒绝草稿编辑和重复提交；前后快照完整 | API/浏览器/审计 |
| W04 | 中途异常、双击、同标识重试、同标识不同内容 | 整体回滚或返回原结果；无重复到访/预约，不同内容 409 | 事务/重试测试 |
| U01 | 操作后状态不再符合原筛选 | 清单移出记录，详情保留最新结果，总览计数更新 | 浏览器 |
| U02 | 写失败、写成功但读失败、键盘及窄屏 | 输入保留，不混淆读写结果；焦点/关闭可用，320/390px 无整页溢出 | 浏览器故障/交互 |
| Q01 | 每批结束构建、测试、SQL 静态与 review | 必需用例通过，阻断问题关闭，文档和代码同批提交 | docs/reviews/ |

写测试使用随机独立测试库，当前开发库 53 条场景保持。未来演示新增业务后如实更新基线，不为维持数字删除历史。本轮 3A 验收证据见 `../reviews/2026-11-09-stage3a-review.md`；3B/3C 尚未实施，伪造审核人/登记人和业务写事务验收在对应批次完成。
