# 阶段 3：身份权限与预约登记、提交、审核

日期：2026-11-08。用户授权完成第三阶段，并改善搜索、页面切换与视觉质感。本阶段所有预约操作集中于“进港预约”，总览仅汇总结果。

## 交付批次

1. **交互与布局**：搜索焦点显示真实候选，输入后防抖查询，可鼠标或方向键/Enter 选择；保留自由检索。两页共用稳定外框、侧栏和工具栏，局部加载保留位置，失败时清除失效数据。收敛双重边框、发亮渐变和嵌套卡片；保留冰蓝、船舶图与轻量波浪。
2. **身份权限**：沿用四类单角色账号；ASP.NET Core Cookie、标准密码哈希、请求防伪造、登录限速。姓名/角色来自后端，每次认证请求复核账号及角色启用状态。只读查询保持当前开放边界，写操作必须登录。管理员、调度员可登记/提交，管理员、审核员可审核，记录员不能写预约。
3. **登记与审核**：从现有启用船舶中选择，填到离港时间、作业小时、申报吃水、优先级及箱量；事务创建到访与预约，可存草稿或直接提交。草稿可提交；待审核可批准/驳回，驳回必须有原因。当前批次不开放改写已提交历史、队列/计划联动撤销或基础船舶维护。
4. **联调与交付**：数据库、HTTP、浏览器验收及独立 review；中文小步提交、推送。不同角色用真实账号登录，不做前端角色假切换。

## 数据与接口设计

保留 21 个基本关系、3 个业务视图及原 E-R 联系。新增受控登记/提交过程，不新增业务表；复用现有审核过程，增加审核角色校验。申请编号由后端生成、数据库唯一约束兜底；创建一次到访及其预约，同事务记录审计。重复提交或重复审核返回冲突，无部分写入。前端时间带偏移传送，后端按 UTC 保存；不得发送操作者 ID，后端从 Cookie 会话确定。

- GET `/api/session`：当前身份及防伪造令牌；匿名身份为 null。
- POST `/api/session/login`、`/logout`：验证凭据、签发/清除 HttpOnly Cookie，写请求校验防伪造令牌。
- GET `/api/ships`：启用船舶候选，供登记表单选择，不允许任意文本伪造船舶。
- POST `/api/appointments`：保存草稿或提交，返回预约编号/主键。
- POST `/api/appointments/{id}/submit`：仅草稿转待审核。
- POST `/api/appointments/{id}/review`：仅待审核转批准/驳回。

账号初始化采用应用管理命令和 PasswordHasher，密码不写 SQL、不提交仓库。已有随机哈希的场景操作人继续保留历史引用，不自动改成可登录账号。正式部署需要 HTTPS；本机 localhost 开发 Cookie 可随 HTTP 使用。

## 验收矩阵

| 编号 | 必须满足 |
|---|---|
| S01 | 搜索候选来自 API；输入/清空/无结果/故障、方向键/Enter/Escape、IME 和失焦行为正确 |
| S02 | 两页外框在同一桌面视口尺寸一致；查询期间表格节点及侧栏不重建，切换无整页闪白或滚动跳动 |
| S03 | 320/390px 不整页横向溢出；表单和对话框可键盘操作，减少动态偏好生效 |
| A01 | 凭据正确可登录，错误凭据响应一致；密码哈希不进入 API/日志/审计/版本库 |
| A02 | 未登录写入 401，错误角色 403，缺失防伪造令牌被拒绝；退出后写入失败，停用用户/角色立即失效 |
| W01 | 登记成功同事务生成到访、预约与审计；草稿无提交时间，提交后有时间且状态待审核 |
| W02 | 时间倒置、过去到港、无效/停用船型或船舶、超船舶吃水、非法数值被拒绝且无残留 |
| W03 | 草稿提交成功；重复提交冲突；批准/驳回责任人来自会话；空驳回原因被拒绝 |
| W04 | 两个并发审核至多一个成功；重复或越权操作不会增加审计/改变状态 |
| W05 | 操作后列表、选中详情及总览同步；错误保留表单输入，重复点击被禁用 |
| Q01 | .NET/前端构建、SQL 静态、独立测试库和浏览器检查通过，深度 review 与文件说明更新 |

日常开发库保留原 53 条场景，验收写入优先在随机独立测试库完成；新增用户和实际演示记录应如实记入交付说明，不为维持旧计数删除业务历史。
