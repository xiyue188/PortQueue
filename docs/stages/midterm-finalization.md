# 中期定稿：范围收口与业务说明

日期：2026-11-10。本文件替代上一轮对三个后续查询页的开放安排；3C 登记、编辑、提交和 3B 审核保留。

## 交付边界

中期正式开放总览与进港预约。锚地排队、泊位计划、进出港记录、查询统计均标记待接入；删除上一轮通用查询页及其专用 API，不把已建立的表、视图和过程等同于模块已经完成。保留总览主图四个入口的布局，未开放入口只显示明确的未接入提示，不打开替代列表。

总览主港改为上海洋山深水港。`SH-YS` 是项目内部港口代码，不声称是 UN/LOCODE。基础资料由 SQL 维护；旧青岛港记录保留为外部港口参考，不改写既有航次的上一港/下一港。已知合成设施按可重跑迁移转入新主港，保留主键、业务记录和历史审计；不把旧青岛坐标冒充洋山坐标。

## 本轮界面设计

1. 保留冰蓝商务外框、主图四入口、亮蓝预约环图与港口动态。
2. 删除“作业分布”及锚地/泊位/事件切换长条；用“进港流程”呈现审核后两种路径：需要等泊进入锚地队列，无需等泊直接安排泊位，最终执行靠离泊。它是流程说明，不是实时航迹或当前船位。
3. 预约分布将标题、图形/状态、查看全部入口分成独立布局行；内容决定最小高度，空间不足时总览内部滚动，不让底部按钮溢出面板。
4. 登记权限仍遵循正式功能说明：调度员依据船公司提供的资料代为登记，审核员作决定。表单明确这一职责，不把调度员说成申请船方。船方自助登录不在中期范围。

## 业务依据

原《选题与系统功能说明》明确：主要使用者为港口调度员、预约审核人员和作业记录人员；“调度员依据船公司提供的船舶和本港到访信息登记预约”。修订数据字典保持 ADMIN / DISPATCHER / REVIEWER / RECORDER 四角色。因此本轮不新增船员身份、不放宽登记权限、不创建企业级组织授权。

## 冻结后

先演练并整理中期证据。中期之后分别设计锚地进出与排队、泊位编排与版本、实际作业记录、查询统计；每一项先定义业务任务、权限、输入输出和验收用例，再开发对应专用界面。
