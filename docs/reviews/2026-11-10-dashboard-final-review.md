# 中期看板最终验收与复核

日期：2026-11-10。范围：现有总览、预约筛选与数据口径说明。后续业务模块继续待接入。

## 本轮改动

1. 进港流程在面板内容区居中，桌面四等分节点与连线共用坐标；手机改为纵向。蓝色自绘小船沿主线循环，可暂停，屏外、后台和离开总览停止；减少动画偏好下隐藏小船。动画解释流程方向，不代表 AIS 或船位。
2. 总览每次读取完成后约 30 秒重新查询数据库，翻页读取同样更新概要。登记与审核成功立即刷新。离页和后台不继续轮询，返回时只补充过期快照。
3. 清单直接显示全部和六种状态，不再把草稿、驳回、撤销藏进第二套选择器；各入口均执行真实查询，零结果也保留入口。
4. 三指标通过原生可展开控件按需显示定义。默认保持紧凑布局，Enter、Space 和点击均可操作；展开后面板随内容撑高。
5. 动态页码独立于响应数据保存。失败清除失效数值，但自动恢复、手动重试、显式刷新和业务保存后的刷新均保留请求页码。

## 输入、处理与输出

- 点击“已驳回” → 前端提交状态 REJECTED → API 参数化查询 SQL Server → 返回该状态的全部匹配记录及分页总数；不会只筛最近六条。
- 调度员页面登记并提交 → 既有认证、后端与事务存储过程保存预约 → 当前页面立即刷新；另一个处于总览的页面下次轮询显示新的待审核数量。测试以独立浏览器上下文验证，不冻结登记候选的防抖计时。
- 港口动态在第 2 页时查询失败 → 清除失效数值并显示重试 → 恢复请求仍使用 eventsPage=2 → 返回第 13—24 条真实事件。

## 深度复核与修复

独立视觉审查首轮发现两项问题：指标仅有原生 title，不便键盘/触摸阅读；轮询失败清空响应后可能回到动态第一页。已分别改为可展开定义和独立查询页码，并添加行为断言。最终视觉判定及适用范围见 [独立视觉审查](2026-11-10-dashboard-visual-review.md)。

修复过程中，浏览器边界断言又发现指标展开文本超出固定摘要行；最终改为按内容确定网格行高，桌面与手机均通过。原动态错误测试一直阻断第 2 页，并要求重试回到第 1 页，与新契约冲突；现改为一次 503 后恢复原页，并核对该页首条真实记录，未删除失败场景。

第一次完整回归还因已失效的 LocalDB 临时管道无法创建独立测试库。读取运行中的 sqlservr 进程确认当前管道后，仅为测试进程提供连接覆盖，最终完整回归通过。临时管道随实例重启改变，未写入应用配置，也不是用户启动命令。期间受限工具运行器发生启动错误，部分命令经批准在本机执行；不属于应用启动或构建故障。

## 数据与范围核对

最终只读查询：待审核 10、锚地在场 10、待靠泊计划 4、全部预约 54。三个主指标来自 `database/queries/overview.sql`：PENDING 预约、已有入锚且无离锚的停留记录、CONFIRMED 当前计划。它们单位不同且可能涉及同一艘船，不能相加为总船数；没有限定为今日。

本轮没有新增表、视图、过程、触发器、种子数据、生产 API 或第三方依赖。页面新增预约使用已完成的 3C，批准/驳回使用已完成的 3B。基础资料维护页、锚地排队写入、泊位编排及实际作业页面仍未接入。

## 验收边界

浏览器为本机 Edge；未做其他浏览器、真实手机硬件、屏幕阅读器和长时间压力验收。自动刷新是当前数据库快照查询，不是外部实时航运接口。动画截图冻结时间只用于观察排版；实际运动、暂停和减少动画有独立行为测试。设计检测器本轮共 74 条 advisory，未作为功能失败，也未通过反复运行消除提示。
