日期：2026-11-09。

## 本轮范围

此前候选只取前 6 条且不显示总量，动态只取最近 5 条；二者内容是真实查询，但都缺少继续浏览路径。本轮扩展检索与动态浏览能力，并按真实业务状态适配用户参考图的绿色细节。第三阶段仍只有规划。

| 层次 | 本轮新增 | 保持边界 |
|---|---|---|
| 前端 | 候选总数、每批续载、全部结果；固定标题动态轮播、暂停、翻页；详情选择与清单检索分离；预约流程线 | 保持冰蓝商务布局、两页缓存和原有筛选；不放勾号辅助数字，无登录或业务写操作 |
| 后端 | 总览 eventsPage 参数、页码校验、事件总量及每页 12 条响应；预约主键精确详情接口 | 仍为只读查询，预约列表接口契约不变 |
| SQL | 扩展 `queries/overview.sql` 的事件分页；新增 `appointment-detail.sql` 精确读取详情 | 不变更 DDL、权限、过程、索引或开发库记录 |

## 事实口径

本机核验：53 条预约，42 条进出港事件。主指标为待审核 9、锚地在场 10、待靠泊计划 4。三个指标保持原口径；不添加语义不同的辅助数字或勾号。

数据是此前落库的合成场景，API 从 SQL Server 查询。自动滚动只控制浏览，事件分页时重新读取；尚无 AIS 或实时推送。绿色表示获批及完成的流程状态；流程线不表示经纬度、实际航行距离或时间进度。

## 深度审查

- 查询只含 SELECT，沿用参数化与单语句 RCSI 快照，完整性规则仍由现有数据库对象承担。
- 下拉有总数与完整清单入口，限制的是每次加载量，不是检索范围；新关键词会清除旧候选并取消旧请求。
- “选择详情”不再等同于“按预约号查询”。首次进入预约页加载完整第一页；已访问时保留清单筛选。关键词的草稿、已提交筛选和详情选择分别管理。
- 精确详情 SQL 使用主键等值条件、参数绑定及原列权限；不存在返回 404。详情失败局部重试，不清空清单，用户仍能选择别的记录。
- 轮播事件不复制 DOM 制造假记录；分页前等待阅读，移入/聚焦暂停，手动翻页后保持暂停。
- 页面不可见、离开总览及卸载时停止轮播；事件监听、Observer 和动画帧均有清理。
- 接口失败清除失效数字和事件，显示重试；不以旧数据或 Mock 掩盖错误。
- 扫描器已执行一次，结果为设计文档未列全既有颜色/字号的 advisory 以及新增流程色的登记提示；不将扫描结果冒充视觉验收。

独立审查提出 1 项 P2：清单错误状态会遮住随后成功读取的独立详情。已调整选择结果的优先级，成功详情正常显示，清单保留错误与“重新查询”入口；新增回归后全量 22 项通过。复核代理核对代码、回归用例与三张最新截图，将该项判定为 resolved，最终 disposition 为 ship。此次复核关闭的是上述修复清单，不等同于新的整站全面审查。

## 限制与下一步

本轮没有验证 Safari/Firefox、真实手机软键盘或屏幕阅读器实机；自动测试覆盖的是 Edge 的窄屏、键盘、输入法事件与减少动画偏好。未进行多用户写入下的压力测试。事件偏移分页在并发插入时可能顺移，本阶段单人只读场景不提供跨页持久快照。

下一步按中期答辩演练现有查询链路；第三阶段认证与预约写入仍按独立设计、验收和小步实施推进。
