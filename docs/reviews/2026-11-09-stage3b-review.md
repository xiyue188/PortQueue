# 阶段 3B review：真实登录、完整申报与预约审核

日期：2026-11-09。结论：本批设计、实现、SQL/API、浏览器交互及指定界面审查已完成；3B 可交付，3C 尚未实施。

## 1. 范围和根因

依据 `docs/stages/stage-3b-review-and-usability.md` 实施。先处理登录格式错误被泛化为服务故障、演示账号输入繁琐、总览数字堆叠和详情图文不足，再完成已有待审核预约的批准/驳回。用户随后补充总览改为蓝色层次，已同步协作规则和实际界面。

前阶段已有真实会话、权限策略及只读链路；本轮新增的是开发账号快捷选项、完整审核详情和真实审核端点及页面。不能把本轮表述成仅改前端，也不能把 3B 通过表述成整个预约生命周期已完成。

## 2. 深度审查结论

| 审查点 | 实际处理与结论 |
|---|---|
| 登录错误分类 | 模型校验区分 INVALID_LOGIN_INPUT、INVALID_QUERY、INVALID_INPUT；前端分别处理输入、凭据、令牌、限速和连接问题，错误密码不显示服务不可用 |
| 演示身份 | 用户明确授权公开初始密码 123456；四个账号仍使用标准哈希/真实会话。选项仅返回存在、启用、角色匹配且仍使用默认凭据的账号 |
| 账号初始化 | 显式命令补缺，不在服务启动时重置；保留既有密码、角色和启停状态。生产关闭入口并拒绝专用账号登录 |
| 详情完整性 | 独立完整 DTO/SQL，不扩大列表载荷；显示船舶、公司、申报、到访和审核资料。停用基础资料仍可读取历史引用 |
| 审核责任人 | 从认证声明取主键，禁止客户端覆盖；额外 reviewerId 等字段返回 400 |
| 双层授权 | API 策略限定 ADMIN/REVIEWER；事务内锁定并复核账号/角色启用与角色类型，防止只靠隐藏按钮 |
| 原子提交 | 复用 usp_review_appointment；状态、责任人、数据库时间、前后审计一起成功或回滚；Dapper 等待整个命令完成后才返回成功 |
| 重复与并发 | 复用同港调度应用锁和 PENDING 锁内复核，重复 409；两个 HTTP 客户端在真实数据库锁后竞争，恰好一个提交 |
| 输入边界 | 决定仅批准/驳回、意见最多 1000 字、驳回去除空白后必填；CSRF、非法字段、无效主键和状态有稳定结果 |
| 最小权限 | 新增完整详情必要列读取，仍禁止应用角色直写业务表；实际部署身份与数据库角色验证明确区分 |
| 刷新与选择 | 审核后清单移出原筛选，保留当前结果详情并更新总览；主动换选择/筛选清除原成功提示 |
| 不确定结果 | 失败保留意见；写成功但读失败不误报保存失败；响应丢失先读取最新结果，不自动重发写操作 |
| 视觉语义 | 总览用蓝色图段、清楚文字及真实数值；详情待审核琥珀、草稿中性、批准绿、完成蓝，终止节点不伪装完成 |
| 模型与数据 | 未增加/重建基本关系，仍为 21 表、3 视图、7 过程、8 表级触发器；自动测试不改开发库预约/事件 |

本轮数据库基线曾因旧断言“应用角色不得读取密码哈希”失败：3A 已授权可信 API 必须读取哈希以验证密码，HTTP 响应才是不允许泄露的边界。已将断言更正为可信后端可读、公开响应不包含认证存储记录，再完整运行数据库回归。另修正冒烟数据用调度员审核的问题，改用事务内临时审核员，测试结束回滚。
