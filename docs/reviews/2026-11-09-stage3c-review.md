# 阶段 3C 深度 review 与验收记录

审查范围：总览改进、三个既有视图查询页、预约登记/编辑/提交，以及与 3B 审核的衔接。设计依据为 `docs/stages/stage-3c-registration-and-port-overview.md`。本轮未扩充基本关系或增加企业级基础设施。

## 数据库与 API

- 新过程 `usp_save_appointment` 使用现有单港事务锁，所有分支检查可用账号及登记角色。CREATE 将航次、预约、审计原子提交；EDIT、SUBMIT 在锁内检查草稿状态和审计版本。
- 唯一预约编号承接创建请求键；审计保存原请求指纹及操作者。重放核验创建快照，不会因后续编辑丢失原请求身份；跨操作者、不同内容拒绝。
- 创建指纹前统一小数表示，`8` 与 `8.00` 视为相同数值，避免合法重试被误判为内容冲突；集成用例覆盖尾零变化及编辑后的原始请求重放。
- 时区在 API 明确验证并转换 UTC；数据库再次检查时间顺序、未来到港、时长与窗口、吃水上限、数值精度、启用船舶和 SHIP_TYPE、启用港口。
- 21 基本关系和 3 视图保持不变，过程从 7 个增至 8 个。查询均为仓库静态参数化 SQL。新业务页与候选查询在 `portqueue_probe` 身份下验证可读；直接写表仍拒绝。
- 空候选时 SQL 的 JSON 子查询可能返回 NULL，已在查询源中统一为 `[]`；零结果是正常空列表，不再成为服务错误。
- 新港口配置参数同时更新最小权限验收用例；事件查询按事件时间倒序，队列按锚地和位置，不能用通用位置排序打乱时间线。
- 显示名称整理只匹配旧代码与原名，使用事务和审计，重跑不重复修改。测试证明可从空库恢复完整对象。

## Vue 与交互

- 真实基础资料搜索与选中标识分开；输入法、取消旧请求和序列号避免迟到响应覆盖新候选。未选择实际候选的文本不能作为有效船舶/港口提交。
- 登记抽屉有字段分组、原生表单校验、提交状态及输入保留；关键校验在服务端再次执行。日期控件明确映射北京时间，航次计划只在主动操作时复制申请时间。
- 创建未知响应只用原键原体核对；草稿修改/提交未知结果先查询最新事实。写成功与随后刷新失败分开提示。
- 新查询页实例保留，切换导航不重建清单。分页、关键词及关联预约均通过真实 API；保留原预约搜索、独立详情和审核行为。
- 查询失败保存本次请求的关键词与目标页码；“重新读取”重试该请求，不退回上一次成功条件。真实浏览器用例分别覆盖新关键词失败、翻页失败以及恢复后的页面往返。
- 删除旧作业概要实现，新增业务查询与登记样式按职责分文件。没有加入第三方路由、状态管理或重型表单框架。

## 限制

验收只在本机 SQL Server 2019 LocalDB 和 Edge 执行，开发库业务记录未被自动化写入。没有外网部署、实际生产权限账号、压测、真实 AIS/硬件或跨浏览器验收。LocalDB 所有者仍具有管理员权限，最小权限结论来自隔离库的 `EXECUTE AS portqueue_probe`，不冒称已将本机运行账号降权。

独立视觉 review 最终为 **ship**，范围限于原 F1—F3 定向复核，三项均已解决：手机登记抽屉恢复内距和完整焦点环、宽屏状态标签/数值分别为 16px/22px、失败查询重试保留关键词与目标页码。详见 `2026-11-09-stage3c-visual-review.md`。此结论不是整站重新验收；320px 登记抽屉没有独立截图，三个新查询页的窄屏布局尚未独立视觉验收。
