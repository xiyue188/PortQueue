## 独立 review 与修复

独立审查覆盖上述六张有效截图、原参考与用户指出的问题、新增 SQL/API/查询状态及数据装载逻辑。首次结论为 `fix`，列出两项 P2 可访问性问题：选中行待审核文字对比度 4.18:1；选中导航部分渐变区域约 4.33:1。

统一将待审核文字改为 `#785008`，对选中底色为 4.77:1；当前导航文字改为 `#0757ad`，对渐变最深端为 4.57:1。构建及七项浏览器用例重新通过，六张截图更新。原审查者定点复核为 `ship`，F1、F2 均 `resolved`。该复核仅评分两项修复，不宣称再次进行了整站全面审查。

完整初审没有发现新增 SQL、API 或状态管理存在阻断交付的逻辑缺陷。审查重点包括：RCSI 单语句一致读取、在场数不等于有效队列数、当前确认计划口径、实际事件排序、字符串 ID、取消与迟到请求隔离、旧样例保留主外键和历史事实、重复导入不生成额外审计。

Impeccable 检测器按流程运行一次，输出部分现有颜色、圆角和字号未完整登记的建议；这些不是语法失败，也不作为像素还原证明。按用户确认的视觉方向保留材质与层次，设计文档同步实际变更，不为清除建议重做界面。

## 实施中纠正的问题

Windows ODBC 版 sqlcmd 首次未指定 UTF-8，中文脚本被错误解码并产生语法报错；使用 `-f 65001` 后成功。根因是客户端输入编码，不是表重复创建。运行手册和数据库 README 已明确 `-b -f 65001`；错误批次没有提交部分业务数据。

原已驳回记录审核摘要使用绿色对勾，容易被误认为批准，本轮改为红色拒绝标识。返回总览重置预约筛选，避免把筛选子集误当全局摘要。旧脚本同时识别升级编号，防止名称整理后重新生成原五条预约。

## 明确边界与后续

所有船舶、人员和业务记录为合成场景，未接实时 AIS；IMO 形式与校验位有效不等于真实注册资料。原五条申请时间因已有历史事件而保留，不随展示需求重写。场景历史审核/确认作为归档快照导入，不能用导入脚本代替日常业务写入口。

当前无认证会话，账号区显示“未登录”；已有数据库账号/角色和应用最小权限不等于业务鉴权完成。未来角色由后端会话确定，不能通过前端切换制造授权。下一批先做身份权限设计与验收，再按 3A 登录权限、3B 审核、3C 登记提交逐项实现。

“进出港记录”是用户菜单名；当前模型仍只有入锚、离锚、进港、靠泊、离泊五类事件。没有独立 PORT_LEAVE，不将离泊时间解释为已证实的跨港界离港。独立出港事实若纳入，需要同步评审模型。

此次没有重跑阶段 1 的全部 59 项数据库规则测试，因为过程和约束未改；历史结果仍在原 review 中。未完成业务写页面和真实角色授权不列为本批已经通过的功能。
