# Design System: PortQueue 冰蓝港口工作台

## Overview

**Creative North Star: "冰蓝港口工作台"**

本系统以用户于 2026-11-07 确认的五张 TIDELINE 截图为视觉依据：冰蓝磨砂材质、细白边线、左侧纵向导航、紧凑工具区、船舶场景和清晰的表格选中态。参考位于 `../../docs/design/reference/`；该方向替代此前白底列表与深色顶栏，不能用通用的反玻璃或反卡片建议改写。

这是供中文港口业务人员操作的工作台。视觉身份来自蓝白层次和紧凑比例；中期正式开放“总览”和“进港预约”两页，分别承载全港概况与检索、详情、登记和审核。锚地排队、泊位计划、进出港记录及查询统计均待接入，旧通用查询页已经撤下。图像提供港口场景感，业务文字保持真实、克制。当前文件记录 2026-11-10 中期冻结后的视觉与交互规则；明亮蓝色图形延续用户确认方向，不代表与参考图逐像素一致。

Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining. 删除重复副标题、装饰性说明和调试性质页脚，保留必要字段名、会改变判断的业务口径、错误恢复和无障碍名称。后续业务页面继续使用这套冰蓝商务风格。

**Key Characteristics:**
- 较深冰蓝工作区衬托更亮的玻璃面板与详情栏。
- 深蓝操作按钮、蓝色导航选中态、整行浅蓝记录选中态。
- 船舶场景铺满焦点面板，真实港口名称与已登记设施构成主层级，底部连续暗层承托四个业务入口。
- 明亮蓝、天蓝与深蓝图形呈现真实预约数量；居中的进港路径与沿线小船解释按需等泊与直接安排。
- 摘要底缘只用一道轻量波浪；表格和表单维持规整边界。
- 紧凑中文字段、统一线性图标、可见的键盘焦点与明确状态文字。
- 共用稳定外框和主次栏，查询反馈局限于结果区，页面往返保留操作上下文。

## Colors

冰蓝环境色与明亮的蓝色数量图形成层次，深海军蓝承载正文和主操作；具体记录的语义状态色只用于明确的业务事实。

### Primary

`chart-draft`、`chart-pending`、`chart-approved`、`chart-completed`、`chart-rejected`、`chart-cancelled` 分别映射全港预约六种状态，图段与图例使用同一 token。进港流程使用 `route-main` 的主轨道、`route-bypass` 的虚线旁路、`route-line` 的节点圆点和 `route-label` 的分支注释；小船使用 `route-boat`，图标使用 `route-symbol`，首节点使用 `route-entry`，后三节点用 `route-future` 标明待接入。这些线条解释路径，不编码实时位置或完成比例。

`primary` 是主按钮的纯色深蓝底；`blue` 用于品牌、输入光标与交互强调。`navigation-selected` 用于导航当前项文字，搭配纯色 `navigation-selected-bg`。`navy-hover` 是主按钮悬停色，`focus` 是键盘焦点描边色。`row-selected` 对应真实表格选中背景；不要误用未被表格消费的旧 CSS 变量作为表格色值。

### Secondary

`pending`、`approved`、`completed`、`inactive`、`rejected` 及各自背景用于待审核、已批准、已完成、草稿或已撤销、已驳回。状态始终同时显示中文文字；表格用语义色文字与圆点；总览独立使用六级蓝色色块和深蓝文字，选中摘要与详情用有底色的标签。绿色用于有事实依据的已批准状态，不表达涨幅、额外统计或 AIS 航程。

### Neutral

`canvas` 是外框之外的蓝灰画布；`ink` 是主要正文，`muted` 是辅助信息和搜索占位文字。`glass` 叠在工作区冰蓝渐变之上，`glass-line` 以更柔和的白边描出面板轮廓，`line` 分隔摘要和详情信息。详情比列表更亮，不能把所有面板合并成同一灰蓝平面。`form-surface` 是登记与确认表面的浅冰蓝底，`field-surface` 是登记输入的近白蓝底。`port-code`、`port-divider` 与 `facility-label` 分别用于港口代码、国家分隔线和设施标签，`scene-focus` 为深色场景入口提供浅蓝焦点。

**The 层次 Rule.** 比较参考图时同时检查工作区、列表和详情的净显示颜色；半透明色必须在实际背景上判断。

**The 图形事实 Rule.** 总览的明亮蓝色表示数量与类别，具体预约的语义色表示业务状态。图例逐项对应图形，零值不填造比例，不跨口径比较。

## Typography

**Display Font:** Segoe UI，Microsoft YaHei，sans-serif。

**Body Font:** 同一系统字体栈。Windows 中文操作界面需要清楚的中英数字混排与稳定回退；这里采用系统字体是使用场景和参考密度的选择，不引入宣传页装饰字体。

### Hierarchy

港口名称采用前置 display，代码为 17px，国家为 14px，设施数为 25px；页面和面板标题分别采用 headline、title。表格正文、按钮、搜索和详情字段使用 14px，表头、时间及表内状态为 13px，编号为 12px，登录输入为 16px。摘要数字为 36px；详情场景船名为 24px；预约分布总数为 34px、状态数为 18px、状态标签为 14px。进港流程节点标题为 16px、正文与分支说明为 12px、待接入为 11px；≤1200px 的节点标题收紧为 14px，≤700px 恢复 16px，纵向分支注释为 10px。≥1800px 时，页面/面板标题为 23px/21px，预约状态标签为 16px、数量为 22px、总数为 40px；港口设施标签和业务入口为 16px，流程标题/正文/说明为 19px/15px/13px，主区左右内距增至 28px。登记标题为 24px、分组标题为 17px、字段为 14px；窄屏登记标题为 22px、输入为 16px、港口名称为 27px。未接入对话框标题为 22px、正文为 15px。窄屏详情字段为 13px，摘要数字为 30px，办理时间为 11px。日期、编号及数量采用等宽数字；长字段、船名与意见允许换行。

## Layout

桌面外框最大宽 1600px；视口宽达到 1800px 时，运行实现将外框放宽至 2200px，以匹配用户提供的宽屏验收视口，宽度为视口减 64px，高度为 100dvh 减 48px，最小高 900px，外距为 24px；外框内边距为 0，默认侧栏占 15.2%。主区左右与底部内距为 22px，工具区所在网格行高 78px，主内容区接续填满剩余高度。面板横向与纵向间距统一为 16px；短桌面窗口允许总览内容区内部滚动，外框自身最小高度仍可能形成页面滚动。

总览和进港预约共用稳定外框、侧栏、工具栏及 1.65:1 主次栏；次栏最小宽 270px。总览三行依次为按内容撑高的指标摘要（面板最小高 88px，另留 8px 波浪空间）、按内容决定高度的港口场景与预约分布、最小高 310px 的进港流程与港口动态。摘要默认紧凑，展开定义时由内容增加行高，不允许固定 96px 将说明压出边界。预约分布使用标题、图形/六状态、独立页脚三行，行间距 16px、桌面内距 22px 24px；六状态入口最小高 44px，页脚上分隔线与 10px 顶距、按钮最小高 36px。面板高度随内容增长，查看全部入口始终在圆角面板内，距面板底边至少 16px。短桌面窗口在总览内容区滚动，不压缩状态行或把按钮挤出边界。港口动态每页 12 条，标题和总量/翻页控件固定，正文独立滚动。预约页首行是 88px 选中摘要，其下清单与详情填满余高。

总览通过独立接口读取全港概要和事件，不请求预约清单。完整清单保留查询条件和选中项；详情选择独立于清单查询，候选或港口动态打开详情时，首次进入清单显示全部记录的第一页，之后保留原关键词、状态、页码和每页条数。总览的状态入口属于主动筛选：清除旧关键词并进入对应状态的完整清单，“查看全部预约”同时清除状态限制。普通页面往返不清空筛选、不因导航重复请求，浏览器前进后退恢复对应页面。全港指标不跟随预约筛选；总览可见且处于活动页时，每次读取完成后约 30 秒重新读取数据库快照，离页或后台停止，返回时只有已过期才读取。本页登记和审核成功立即刷新；显式刷新更新总览和已访问的完整清单，首次进入完整清单时加载。动态请求页码独立保存，定时读取、失败恢复、手动重试和显式刷新均保留原请求页；取消旧请求与序列保护防止迟到响应覆盖。查询只更新结果区，已有表格与滚动位置保留到请求结束，不用整页过渡遮盖布局变化。

- ≤1250px：侧栏固定 170px，外框两侧合计留 48px；主区左右内距收紧为 18px 和 13px，隐藏完整清单船舶缩略图。
- ≤1200px：港口场景的四个业务入口改为两列，场景最小高 350px，港口资料内距收紧，预约分布内距为 20px。
- ≤1000px：外框高度改为自然内容高度，最小高为 100dvh 减 28px，外距 14px；侧栏 155px，两侧合计留 28px。日期隐藏，港口场景与预约分布改为单列，进港流程与港口动态、清单与详情纵向排列；总览内容区改为自然溢出，港口动态高 330px，完整清单记录区高 420px。恢复清单缩略图，完整详情保持单列；环图最大宽 180px。
- ≤700px：外框两侧合计留 20px；导航由按钮展开为两列菜单，同时显示账号入口，搜索独占一行，详情回到单列。场景最小高 370px，底部四个入口保持两列；预约分布按内容撑开，内距 20px 16px、页脚顶距 12px。进港流程改为纵向四节点，旁侧分支跨过锚地等泊连接泊位安排。搜索高 44px，常用筛选和分页控件至少 40px。
- 手机预约表格保留 570px 最小宽度并显示横向滚动提示。不得通过挤掉状态和时间来消除滚动。页面基础最小宽度 320px；已撤下的业务查询表格尺寸不再属于当前设计。
- 登记抽屉宽为 680px 与实际可用包含块宽度中的较小值，最大宽 100%，高 100dvh；桌面表单左右内距 32px，两列字段间距 18px 20px。≤700px 时去掉外角、字段改为单列、左右内距 20px，底部操作可换行。宽度不能使用 100vw 抵消根页面预留滚动条空间。

每次视觉改动保存桌面与窄屏截图，并对照五张用户参考。中期必需视口为 1440×900、1920×1080、2470×900、1280×720、973×800、390×844、320×740；构建通过不替代视觉验收。

## Elevation & Depth

深度来自冰蓝渐变底、半透明白蓝面板、柔和白边与少量结构阴影。普通面板采用 16px 背景模糊，侧栏采用 18px；侧栏是单层半透明浅底，列表与详情分别使用较亮的半透明背景。主按钮用纯色底和细浅边建立操作边界，无内阴影。候选浮层有独立浅底与阴影，浮在工具区下方，不挤压内容区。

### Shadow Vocabulary

- 外框：`0 14px 40px rgba(28, 55, 77, .1)`，提供轻量环境层次。
- 搜索候选浮层：`0 10px 30px rgba(25, 53, 74, .18)`，区分浮层与后方内容。
- 登录对话框：`0 14px 40px rgba(28, 55, 77, .18)`，配合半透明深蓝遮罩建立模态层次。
- 登记抽屉：`-14px 0 40px rgba(28,55,77,.15)`，强调右侧受保护操作面。
- 基础资料候选：`0 10px 24px rgba(27,65,95,.14)`，让选择列表浮在表单字段上方。

**The 场景文字 Rule.** 港口场景图铺满焦点容器；底部深色渐变位于左侧浅色蒙层之上，让业务入口白字落在连续深色背景上；港口名称和设施位于左上浅层，不以泛化大标题覆盖船舶主体。

## Shapes

面板与外框使用前置 token 中的圆角层级，搜索框略圆于按钮，登录输入沿用控件圆角。1px 白色透明边线持续表达磨砂玻璃边缘，表格内部保持轻分隔。图标遵循 24px 画布、1.8px 圆端圆角描边，默认显示 22px；品牌波纹是独立标志。状态点和账号图标底使用圆形；摘要图标使用透明底，不再添加圆形底块。

概况摘要的底缘使用 10px 高的波浪遮罩；曲线只提供少量航运特征，不能伸入字段网格或在每块容器重复。登记输入使用 6px 圆角，流程分支使用轻量圆角折线；登记抽屉只在桌面左侧保留 16px 外角。表格、表单和密集信息区保持整齐边界。

## Components

### Buttons

深蓝主按钮承载刷新、重新查询、登录与提交审核；纯色 `primary` 底、白字、细浅边，悬停转为 `navy-hover`。禁用透明度为 0.5。图标按钮基准 34px 方形，浅冰蓝底，悬停近白且图标转蓝；禁用透明度为 0.55。焦点使用 2px 描边和 3px 外偏移。按钮与表格行仅以 140ms ease-out 过渡背景色与文字色；系统要求减少动态时关闭。总览状态入口最小高 44px，不能把现有较小图标控件描述为全部达到了 44px。

### Inputs / Fields

顶部搜索包含搜索图标、输入、非空时的清除按钮和“查询”按钮，整体采用磨砂浅底；聚焦容器使用 `focus` 的 2px 轮廓，外偏移 2px，placeholder 使用 `muted`。真实 API 每批返回六条候选，浮层显示匹配总量、船名、预约编号、申请到港时间和状态，并提供“加载更多”与“查看全部结果”；上下键切换，Enter 选择高亮候选或提交自由关键词，Escape、移出焦点及点击外部关闭。中文输入法合成期间不提交、不请求候选；输入防抖 220ms，旧请求取消并用序号防止旧响应覆盖新结果。无候选时仍允许自由提交；候选读取失败提供“重试”，重试先恢复输入焦点，保持浮层打开。

输入草稿与已提交条件分开，状态切换基于最近已提交的查询意图，不能夹带尚未提交的草稿。选择候选只进入预约工作区并选择详情，不按该预约编号筛掉其他记录，搜索输入恢复已提交的清单关键词。只有主动查询（含“查看全部结果”）、状态筛选、分页或每页条数选择、重置/清除条件改变清单；“查看全部结果”提交当前输入关键词并清除状态限制。清单显示可清除的已提交关键词，清除关键词保留当前状态条件。状态筛选直接提供“全部、草稿、待审核、已批准、已驳回、已撤销、已完成”七个按钮，采用同一状态枚举和 aria-pressed，窄屏自然换行；不再设置重复的全状态下拉框。分页大小选择器保持原生键盘行为。

基础玻璃面板共用细白边、圆角和背景模糊。总览摘要呈三列，仅显示“待审核预约”“锚地在场”“待靠泊计划”及全港查询值，不在主指标旁堆放额外绿色辅助计数或勾号。三项使用原生 details/summary，默认折叠，带小型展开箭头和可见焦点；Enter、Space、鼠标与触摸均可按需打开定义。说明文字为 12px、行高 1.55，面板随内容撑高；不只依赖 title 悬停。首次读取未完成或失败时显示破折号，后台更新保留现有快照至请求结束，失败清除失效数字。中期收口时开发库查询到 54 条预约，包含持久化合成场景与用户新增申请；该数值仅作证据快照，所有列表、状态和统计均通过 API 查询数据库；数据性质记录在产品和数据库文档中，不增加界面角标。详情栏使用更亮的底色和左右对齐的字段组；长文本可折行，审核意见保留原有换行。

### Port Overview

下方“进港流程”解释业务路径，四节点依次为“预约审核”“锚地等泊”“泊位安排”“靠离泊作业”；后三节点均标“待接入”。流程内容在面板可用空间中居中，图形最大宽 1000px；桌面节点中心按四等分对齐主轨道，独立虚线旁路由审核跨过锚地连接泊位，说明“无需等泊，直接安排”。≤700px 时图形最大宽 330px、高 360px，四节点纵向排列，侧边旁路保留跨越关系。自绘蓝色帆船沿主线以 16 秒循环移动，首尾透明度平滑收放；它仅表达方向，不绑定任何船舶或 AIS 位置。面板提供暂停/继续按钮，屏外、浏览器后台和离开总览时暂停原生 SVG 时间轴，系统减少动画时隐藏小船并停用动画按钮；恢复时尊重用户暂停状态。节点不作为后续模块入口、不报告办理进度；原“作业分布”长条、三项切换和关联查询页脚已经删除。

### Recent Events

“港口动态”沿用玻璃面板和轻分隔线，每条展示船名、实际事件类型和发生时间。接口每页返回 12 条，当前已核对总量为 42 条，界面始终读取 API 返回的实际总量并展示当前范围，不将 42 固定在代码中。固定标题旁提供暂停/继续及较新/较早动态按钮；正文按约 18px/s 自动滚动，在开始、到达底部或循环前停留 1.8 秒，有更多页时继续读取下一页，末页回到第一页。

鼠标悬停或键盘焦点停留在正文时暂时停止；手动翻页、滚轮或触摸阅读后保持暂停，直到用户主动继续。页面处于后台、离开总览、正文离开可见区域、加载中或出错时停止；减少动态效果偏好默认暂停。窄屏将时间移到下一行，保持船名和事件可扫读。点船名只读取关联预约详情，保留清单筛选与分页。查询失败提供“重试”，重试保留失败的目标页，不强制退回第一页；没有记录时显示空状态，不填入虚构事件。

### Loading / Empty / Error

反馈限制在对应内容区。首次加载显示骨架，后续查询保留已有表格 DOM、滚动位置与选中详情，表格降至 0.52 透明度并置为不可交互；顶部 2px 细线和“正在更新…”提示处理状态，不播放伸缩动画。请求结束前旧数据仍对应旧筛选、旧页码，成功后同步替换条件、数据与计数，避免把旧数据冒充新结果。

清单请求失败后清空失效记录和计数，保留失败的查询意图用于“重新查询”；分页显示“查询未完成”，不以旧清单推导详情。详情读取具有独立加载、错误和“重试详情”入口，失败时清除该次失效详情；清单错误不得遮住成功读取或明确选中的独立详情，详情错误也不替换清单结果。空结果提供清除筛选或返回第一页。取消旧请求和请求序号共同隔离过期响应，不以假记录填补空白；港口动态正文滚动与流程方向小船分别管理暂停和可见性，不把局部动画扩展到整页切换。


### Stage 3B business surface

预约详情在已有亮色详情栏中放置来源有记录的港口场景和办理进度。进度只表达 DRAFT、PENDING、APPROVED、COMPLETED 的预约办理事实；REJECTED/CANCELLED 以终止节点收束。当前节点按事实着色：草稿中性、待审核琥珀、已批准绿色、已完成蓝色；颜色始终伴随中文状态文字。CANCELLED 仅显示“预约建立 → 已撤销”，不推断此前获批。完整详情按主键读取船舶、船型、船公司、IMO/MMSI、尺寸、吃水、吨位、货物、预计作业、优先级、危险品、特殊要求、提交及审核事实，到访计划与前后港可展开。审核确认框最大宽 460px，展示绑定的船名和预约号，完整详情读取成功、PENDING 且会话有权限才显示按钮。批准意见选填、驳回原因必填，最多 1000 字；审核人来自会话，CSRF 与服务端授权保护写入；事务统一更新状态、审核人、数据库时间和审计。成功后刷新清单、详情与总览，记录离开待审核清单仍保留所选详情。保存成功但读取失败提示无需再次审核；冲突、超时或响应丢失先查看最新状态，不自动重放写入。四个开发账号选项只作为真实凭据填充器，不能替代后端授权。

总览环图是全港查询结果的可视化表达，不新增业务事实；进港流程与方向动效独立解释业务路径，不使用实时进度暗示、彩虹色或比较基准不明的装饰数字。

### Stage 3C registration / draft / submit

登记采用原生模态侧栏，沿用浅冰蓝表面、细蓝字段边线、深蓝提交按钮与可见焦点。标题为“登记进港预约”或“编辑预约草稿”，标题下显示“调度员依据船方提供的资料代为登记。”，按“船舶与本次到访”“申请与作业”“补充要求”分组。底部操作粘附于滚动容器，错误与恢复入口位于操作上方；保存时禁用字段和重复写入。ADMIN/DISPATCHER 可登记、编辑与提交，只有 DRAFT 显示“编辑草稿”和“提交审核”。

“本次到访预计时间”与申请时间独立维护，仅点击“沿用申请时间”才复制，时间按 UTC+8 解释。新建提供“保存草稿”和“提交审核”；编辑先保存，再在绑定船名与预约号的确认框中提交，明确告知提交后申报内容锁定。失败保留输入；未知结果显示“核对登记结果”“读取最新内容”或“查看最新状态”。创建沿用原请求键和原内容核对，编辑及提交先读取事实，不盲目覆盖并发修改。已保存但刷新失败与保存失败分开表达；业务处理细节见 PRODUCT.md 与阶段文档。

### Midterm scope boundary

中期保留总览、进港预约与真实身份认证。锚地、泊位、实际记录和统计的专用任务、权限与验收设计留待中期后；已撤下的通用查询页只在历史证据中存在，不保留其表格布局作为当前规范，也不以现成表/视图代表业务页面完成。

## Do's and Don'ts

### Do:

- **Do** 对照用户五张参考图保留冰蓝磨砂、紧凑侧栏、深蓝操作和明亮详情层次。
- **Do** 使用数据库查询字段和独立的全港概况，保持申请、计划、实际时间与 UTC+8 时区语义清楚。
- **Do** 使用明亮蓝、天蓝与深蓝数量图，保持图例对应和同类比较，主图显示真实港口资料与已登记设施。
- **Do** 让布局承担解释，保留必要字段、错误恢复和无障碍名称；素材来源与合成数据性质保存在文档和元数据。
- **Do** 仅在摘要或场景区域少量使用海浪边，表格和表单保持整齐边界。
- **Do** 保留可见键盘焦点、状态文字、局部横向滚动与移动端导航。
- **Do** 延续共用外框与主次栏比例，导航保留筛选和选中项，查询使用局部反馈并保留表格滚动位置。
- **Do** 将详情选择与清单查询分开，已提交关键词可见且可清除；候选与动态展示真实总量并可继续浏览。
- **Do** 让动态标题和控件固定，尊重阅读暂停、页面可见性及减少动态效果偏好。
- **Do** 让登记侧栏按实际可用宽度收缩，移动表单保留 20px 内距和完整焦点；失败保留输入，重试保留请求意图。
- **Do** 在桌面、短窗口、宽屏与窄屏保存有效截图，核对预约分布入口在面板内且底部留白至少 16px 后再评价视觉完成度。

### Don't:

- **Don't** 恢复白底列表或深色顶栏，或用通用风格建议抹掉用户指定的玻璃材质。
- **Don't** 复制海报大字、水印、社交账号，或把裁片冒充真实船舶照片。
- **Don't** 在业务界面添加 Demo、课程演示数据、本地演示、更新时间、船舶示意角标或重复的排序说明行。
- **Don't** 为凑版式捏造 AIS、地图、登录身份、通知、全港统计或未实现的操作。
- **Don't** 在三个主指标旁添加口径不同的绿色辅助计数或无比较基准的勾号数字，也不要用预约申请时间推算 AIS 航程。
- **Don't** 在中期重新开放后续通用列表，或将进港流程动效解释为实时船位与已开放操作。
- **Don't** 用构建成功、静态预览或局部修复结论声称逐像素还原和整站全面验收。
