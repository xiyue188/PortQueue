# Design System: PortQueue 冰蓝港口工作台

## Overview

**Creative North Star: "冰蓝港口工作台"**

本系统以用户于 2026-11-07 确认的五张 TIDELINE 截图为视觉依据：冰蓝磨砂材质、细白边线、左侧纵向导航、紧凑工具区、船舶场景和清晰的表格选中态。参考位于 `../../docs/design/reference/`；该方向替代此前白底列表与深色顶栏，不能用通用的反玻璃或反卡片建议改写。

这是供中文港口业务人员操作的工作台。视觉身份来自蓝白层次和紧凑比例；“总览”呈现跨业务概况，“进港预约”承载检索和详情。图像提供港口场景感，业务文字保持真实、克制。当前文件记录 2026-11-09 已实现界面的视觉与交互规则，不代表与参考图逐像素一致。

Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining. 删除重复副标题、装饰性说明和调试性质页脚，保留必要字段名、会改变判断的业务口径、错误恢复和无障碍名称。后续业务页面继续使用这套冰蓝商务风格。

**Key Characteristics:**
- 较深冰蓝工作区衬托更亮的玻璃面板与详情栏。
- 深蓝操作按钮、蓝色导航选中态、整行浅蓝记录选中态。
- 船舶场景铺满焦点面板，底部连续暗层承托白色业务环节文字。
- 摘要底缘只用一道轻量波浪；表格和表单维持规整边界。
- 紧凑中文字段、统一线性图标、可见的键盘焦点与明确状态文字。
- 共用稳定外框和主次栏，查询反馈局限于结果区，页面往返保留操作上下文。

## Colors

主色是带灰度的冰蓝环境色，以深海军蓝承载正文和操作，状态色只用于明确的业务状态。

### Primary

`primary` 是主按钮的纯色深蓝底；`blue` 用于品牌、输入光标与交互强调。`navigation-selected` 用于导航当前项文字，搭配纯色 `navigation-selected-bg`。`navy-hover` 是主按钮悬停色，`focus` 是键盘焦点描边色。`row-selected` 对应真实表格选中背景；不要误用未被表格消费的旧 CSS 变量作为表格色值。

### Secondary

`pending`、`approved`、`completed`、`inactive`、`rejected` 及各自背景用于待审核、已批准、已完成、草稿或已撤销、已驳回。状态始终同时显示中文文字；表格用语义色文字与圆点；总览独立使用六级蓝色色块和深蓝文字，选中摘要与详情用有底色的标签。绿色用于有事实依据的已批准状态，不表达涨幅、额外统计或 AIS 航程。

### Neutral

`canvas` 是外框之外的蓝灰画布；`ink` 是主要正文，`muted` 是辅助信息和搜索占位文字。`glass` 叠在工作区冰蓝渐变之上，`glass-line` 以更柔和的白边描出面板轮廓，`line` 分隔摘要和详情信息。详情比列表更亮，不能把所有面板合并成同一灰蓝平面。

**The 层次 Rule.** 比较参考图时同时检查工作区、列表和详情的净显示颜色；半透明色必须在实际背景上判断。

## Typography

**Display Font:** Segoe UI，Microsoft YaHei，sans-serif。

**Body Font:** 同一系统字体栈。Windows 中文操作界面需要清楚的中英数字混排与稳定回退；这里采用系统字体是使用场景和参考密度的选择，不引入宣传页装饰字体。

### Hierarchy

港口场景、页面和面板标题分别采用前置 display、headline、title；表格正文、按钮、搜索和详情字段使用 14px，表头、时间及表内状态为 13px，编号为 12px，登录输入为 16px。摘要数字为 36px；详情场景船名为 24px；状态总数为 34px、各状态数为 18px。作业概要的队列、计划、累计事件数字分别为 21px、24px、17px。视口达到 1800px 时，场景/页面/面板标题为 34px/23px/21px，详情字段、表格船名、状态入口为 16px，时间与作业标签为 15px，详情场景船名为 28px；主区左右内距增至 28px。窄屏详情字段为 13px，摘要数字为 30px，办理时间为 11px。日期、编号及数量采用等宽数字；长字段、船名与意见允许换行。

## Layout

桌面外框最大宽 1600px；视口宽达到 1800px 时，运行实现将外框放宽至 2200px，以匹配用户提供的宽屏验收视口，宽度为视口减 64px，高度为 100dvh 减 48px，最小高 900px，外距为 24px；外框内边距为 0，默认侧栏占 15.2%。主区左右与底部内距为 22px，工具区所在网格行高 78px，主内容区接续填满剩余高度。面板横向与纵向间距统一为 16px；窄于内容最小高度的桌面视口允许页面自然滚动。

总览和进港预约共用稳定外框、侧栏、工具栏及 1.65:1 主次栏；次栏最小宽 270px。总览采用三行：96px 高的摘要区域（含 8px 波浪留白）、最小高 320px 的港口场景与全量预约状态分布、最小高 330px 的作业概要与港口动态；后两行按 0.95:1 分配余高。预约分布内左侧为细环、右侧为六行状态入口，作业概要按锚地排队、泊位计划、累计执行分为三行。港口动态显示独立总览接口返回的实际事件，每页 12 条，标题和总量/翻页控件固定，正文在独立视口内滚动并可继续翻页。预约页首行是 88px 选中摘要，其下清单与详情填满剩余高度。桌面表格和详情在各自区域内滚动，保留标题、筛选和分页位置。

总览通过独立接口读取全港概要和事件，不请求预约清单。完整清单保留查询条件和选中项；详情选择独立于清单查询，候选或港口动态打开详情时，首次进入清单显示全部记录的第一页，之后保留原关键词、状态、页码和每页条数。总览的状态入口属于主动筛选：清除旧关键词并进入对应状态的完整清单，“查看全部预约”同时清除状态限制。普通页面往返不清空筛选、不因导航重复请求，浏览器前进后退恢复对应页面。全港指标不跟随预约筛选；显式刷新更新总览和已访问的完整清单，首次进入完整清单时加载。查询只更新结果区，已有表格与滚动位置保留到请求结束，不用整页过渡遮盖布局变化。

- ≤1250px：侧栏固定 170px，外框两侧合计留 48px；主区左右内距收紧为 18px 和 13px，隐藏完整清单船舶缩略图。
- ≤1000px：外框高度改为自然内容高度，最小高为 100dvh 减 28px，外距 14px；侧栏 155px，两侧合计留 28px。日期隐藏，作业概要与港口动态、清单与详情纵向排列；港口动态高 330px，完整清单记录区高 420px。恢复清单缩略图，完整详情保持单列；场景与状态分布暂按 1.7:1 并排，所在区域最小高 320px。
- ≤700px：外框两侧合计留 20px；导航由按钮展开为两列菜单，同时显示账号入口，搜索独占一行，场景与状态分布上下排列，详情回到单列。场景最小高 240px，状态分布最小高 320px，场景底部业务环节分为两列。搜索高 44px，常用筛选和分页控件至少 40px。
- 手机表格保留 570px 最小宽度，在局部横向滚动并显示提示；不得通过挤掉状态和时间来消除滚动。页面基础最小宽度 320px。

每次视觉改动保存桌面与窄屏截图，并加入用户参考自身 973×640 尺寸的对照检查；构建通过不替代视觉验收。

2026-11-09 阶段 3A 和 3B 的有效截图位于仓库根 `.impeccable/review/`：`desktop-overview.png`、`desktop-appointments.png`、`user-2470-overview.png`、`user-2470-appointments.png`、`reference-973-appointments.png`、`mobile-overview.png`、`session-authenticated.png`、`mobile-login.png`、`stage3b-login.png`、`stage3b-review-confirm.png`、`stage3b-approved.png`、`stage3b-mobile-review.png`；登录窄屏截图视口为 390×844。首轮 3B 独立审查发现当前节点误用获批绿色的 P2，已修正。最终 finish review 针对“办理节点状态颜色”和“总览蓝色层次”复核为 ship；此记录限定于这两项修正，不代表后续业务页已经验收。

## Elevation & Depth

深度来自冰蓝渐变底、半透明白蓝面板、柔和白边与少量结构阴影。普通面板采用 16px 背景模糊，侧栏采用 18px；侧栏是单层半透明浅底，列表与详情分别使用较亮的半透明背景。主按钮用纯色底和细浅边建立操作边界，无内阴影。候选浮层有独立浅底与阴影，浮在工具区下方，不挤压内容区。

### Shadow Vocabulary

- 外框：`0 14px 40px rgba(28, 55, 77, .1)`，提供轻量环境层次。
- 搜索候选浮层：`0 10px 30px rgba(25, 53, 74, .18)`，区分浮层与后方内容。
- 登录对话框：`0 14px 40px rgba(28, 55, 77, .18)`，配合半透明深蓝遮罩建立模态层次。

**The 场景文字 Rule.** 港口场景图铺满焦点容器；底部深色渐变位于左侧浅色蒙层之上，让业务环节白字落在连续深色背景上。

## Shapes

面板与外框使用前置 token 中的圆角层级，搜索框略圆于按钮，登录输入沿用控件圆角。1px 白色透明边线持续表达磨砂玻璃边缘，表格内部保持轻分隔。图标遵循 24px 画布、1.8px 圆端圆角描边，默认显示 22px；品牌波纹是独立标志。状态点和账号图标底使用圆形；摘要图标使用透明底，不再添加圆形底块。

概况摘要的底缘使用 10px 高的波浪遮罩；曲线只提供少量航运特征，不能伸入字段网格或在每块容器重复。表格、表单和密集信息区保持整齐边界。

## Components

### Buttons

深蓝主按钮承载刷新、重新查询和登录；纯色 `primary` 底、白字、细浅边，悬停转为 `navy-hover`。禁用透明度为 0.5。图标按钮基准 34px 方形，浅冰蓝底，悬停近白且图标转蓝；禁用透明度为 0.55。焦点使用 2px 描边和 3px 外偏移。按钮与表格行仅以 140ms ease-out 过渡背景色与文字色；系统要求减少动态时关闭。总览状态入口默认最小高 42px，窄屏为 44px，视口达到 1800px 时为 52px，不能把现有较小图标控件描述为全部达到了 44px。

### Inputs / Fields

顶部搜索包含搜索图标、输入、非空时的清除按钮和“查询”按钮，整体采用磨砂浅底；聚焦容器使用 `focus` 的 2px 轮廓，外偏移 2px，placeholder 使用 `muted`。真实 API 每批返回六条候选，浮层显示匹配总量、船名、预约编号、申请到港时间和状态，并提供“加载更多”与“查看全部结果”；上下键切换，Enter 选择高亮候选或提交自由关键词，Escape、移出焦点及点击外部关闭。中文输入法合成期间不提交、不请求候选；输入防抖 220ms，旧请求取消并用序号防止旧响应覆盖新结果。无候选时仍允许自由提交；候选读取失败提供“重试”，重试先恢复输入焦点，保持浮层打开。

输入草稿与已提交条件分开，状态切换基于最近已提交的查询意图，不能夹带尚未提交的草稿。选择候选只进入预约工作区并选择详情，不按该预约编号筛掉其他记录，搜索输入恢复已提交的清单关键词。只有主动查询（含“查看全部结果”）、状态筛选、分页或每页条数选择、重置/清除条件改变清单；“查看全部结果”提交当前输入关键词并清除状态限制。清单显示可清除的已提交关键词，清除关键词保留当前状态条件。原生状态选择器与分页大小选择器保持原生键盘行为。

### Navigation

纵向菜单采用线性图标与中文名称；当前项用纯浅蓝底、深蓝文字，并以 `aria-current` 表达。可用入口为“总览”“进港预约”；“锚地排队”“泊位计划”“进出港记录”“查询统计”禁用且显示“待接入”。账号区位于侧栏底部，匿名时显示“未登录”和“登录”；登录后显示后端会话返回的姓名、角色与“退出”。窄屏展开导航后保留账号入口，不使用前端角色切换冒充授权。

### Session Account / Login

登录采用原生模态 `dialog`，沿用冰蓝浅底、细白边、面板圆角和深蓝主按钮。对话框宽为 440px 与视口减 32px 中的较小值，最大高为 100dvh 减 40px，内容可滚动；桌面内距 24px，窄屏为 20px。用户名和密码竖向排列，输入最小高 42px，浅色底与细蓝边保证字段边界清晰。

打开时读取当前会话并将焦点移入用户名，原生模态约束焦点，Escape 与关闭按钮均可关闭。处理时禁用输入和提交；提交后或关闭时清空密码。登录失败在表单内显示错误与“刷新会话”，账号区读取失败显示“账号服务不可用”和“重试”，不继续展示失效身份。登录、退出和身份读取使用真实 Cookie 会话；姓名、角色和权限来自后端。只读查询继续允许匿名访问，3B 审核按钮已接入，3C 登记提交尚未开放。

四个真实账号选项以两列展示管理员陈宁、调度员周航、审核员林悦、记录员许舟；仅 Development 且显式启用时由后端返回，公开初始密码为 123456。选择只填入凭据并聚焦登录按钮，仍须通过后端密码验证，不能用前端切换角色。密码可显示/隐藏，提交或关闭后清空。输入格式、无效凭据、会话变化、限速、连接故障分别提示；会话变化或连接错误提供“刷新会话”，不把所有错误归为服务不可用。

### Chips

状态标签有圆点、中文名称和对应底色；表格版本去掉底色。筛选标签为独立按钮，选中时白色磨砂底、加深加粗文字，并用 `aria-pressed` 表达。不要把状态只编码为颜色。

### Cards / Containers

基础玻璃面板共用细白边、圆角和背景模糊。总览摘要呈三列，仅显示“待审核预约”“锚地在场”“待靠泊计划”及全港查询值，不在主指标旁堆放额外绿色辅助计数或勾号；加载或错误显示破折号，不保留过期数字。当前开发库的 53 条预约是持久化合成场景，所有列表、状态和统计均通过 API 查询数据库；数据性质记录在产品和数据库文档中，不增加界面角标。详情栏使用更亮的底色和左右对齐的字段组；长文本可折行，审核意见保留原有换行。

### Port Overview

港口图像为铺满裁切的场景焦点，左上显示“港口业务概况”；下方按进港预约、锚地排队、泊位计划、进出港记录展示业务环节，文字与线性图标落在连续深色背景上。场景是全港概况的视觉锚点，不承载单船记录、轮播或办理进度。

右侧“预约分布”覆盖草稿、待审核、已批准、已完成、已驳回、已撤销六种状态。细环半径 62、描边 12px，段长以各状态真实数量除以总数计算，并保留少量段间空隙；中央显示总量。六级蓝色依次为 #b6cbd9、#719ebc、#3d759d、#183f60、#5988a8、#93b1c5；图例使用对应蓝色色块、深蓝状态文字和精确计数，底部提供“查看全部预约”。点击状态清除旧关键词并打开对应完整清单；加载时禁用入口，失败清除失效数据，零值不画虚假扇区。

下方“作业概要”延续玻璃面板和轻分隔。锚地排队显示等待分配、已分配；泊位计划以整齐的标签和值显示草拟、已确认、执行中，移除重复小图标；累计执行显示进港、靠泊、离泊实际事件数量。总览三类图形统一使用深蓝、雾蓝、灰蓝层次，环图描边为 12px，锚地组成条为 8px，累计事件条为 5px，状态文字和真实数值承担主要识别。锚地条按等待/已分配合计计算比例；累计事件条相对三项最大值计算长度，未知显示破折号，零值为空条。不同业务口径在各自行内表达，不把有效队列数当作实际在场量，也不把累计事件写成今日量。

总览与详情办理场景共用用户提供的 `src/assets/port-scene.png`（733×826），来源与用途保存于同名 `.json`。原有 `vessel-reference.png` 用于清单缩略图和选中摘要，其裁切来源保存在 `src/assets/vessel-reference.png.json`。两者均为全局装饰，不绑定具体船舶，图片使用空 `alt`；不显示图片来源角标，不把场景图冒充记录的实船照片。不得展示原海报水印、社交账号或背景大字。

### Appointment Table

表格显示船舶与预约编号、申请到港及预约状态。普通单元格内边距为 12px 8px；整行悬停浅蓝，选中使用 `row-selected`。行内船舶按钮提供键盘选择，整行点击只是快捷方式。固定倒序写在无障碍表格标题中，表头保留必要的 UTC+8 时区信息；不额外显示“全部申请日期”等排序说明行，不放置虚假的可排序控件。状态筛选、已提交关键词、每页条数、总数和分页集中在“进港预约”，总览提供全量状态入口与“查看全部预约”。选择候选或港口动态不改变清单条件；所选详情不在当前清单页时，不伪造该页选中行。

### Recent Events

“港口动态”沿用玻璃面板和轻分隔线，每条展示船名、实际事件类型和发生时间。接口每页返回 12 条，当前已核对总量为 42 条，界面始终读取 API 返回的实际总量并展示当前范围，不将 42 固定在代码中。固定标题旁提供暂停/继续及较新/较早动态按钮；正文按约 18px/s 自动滚动，在开始、到达底部或循环前停留 1.8 秒，有更多页时继续读取下一页，末页回到第一页。

鼠标悬停或键盘焦点停留在正文时暂时停止；手动翻页、滚轮或触摸阅读后保持暂停，直到用户主动继续。页面处于后台、离开总览、正文离开可见区域、加载中或出错时停止；减少动态效果偏好默认暂停。窄屏将时间移到下一行，保持船名和事件可扫读。点船名只读取关联预约详情，保留清单筛选与分页。查询失败提供“重试”，没有记录时显示空状态，不填入虚构事件。

### Loading / Empty / Error

反馈限制在对应内容区。首次加载显示骨架，后续查询保留已有表格 DOM、滚动位置与选中详情，表格降至 0.52 透明度并置为不可交互；顶部 2px 细线和“正在更新…”提示处理状态，不播放伸缩动画。请求结束前旧数据仍对应旧筛选、旧页码，成功后同步替换条件、数据与计数，避免把旧数据冒充新结果。

清单请求失败后清空失效记录和计数，保留失败的查询意图用于“重新查询”；分页显示“查询未完成”，不以旧清单推导详情。详情读取具有独立加载、错误和“重试详情”入口，失败时清除该次失效详情；清单错误不得遮住成功读取或明确选中的独立详情，详情错误也不替换清单结果。空结果提供清除筛选或返回第一页。取消旧请求和请求序号共同隔离过期响应，不以假记录填补空白；自动动态只作用于港口动态正文，并提供上述阅读暂停行为。


### Stage 3B business surface

预约详情在已有亮色详情栏中放置来源有记录的港口场景和办理进度。进度只表达 DRAFT、PENDING、APPROVED、COMPLETED 的预约办理事实；REJECTED/CANCELLED 以终止节点收束。当前节点按事实着色：草稿中性、待审核琥珀、已批准绿色、已完成蓝色；颜色始终伴随中文状态文字。CANCELLED 仅显示“预约建立 → 已撤销”，不推断此前获批。完整详情按主键读取船舶、船型、船公司、IMO/MMSI、尺寸、吃水、吨位、货物、预计作业、优先级、危险品、特殊要求、提交及审核事实，到访计划与前后港可展开。审核确认框最大宽 460px，展示绑定的船名和预约号，完整详情读取成功、PENDING 且会话有权限才显示按钮。批准意见选填、驳回原因必填，最多 1000 字；审核人来自会话，CSRF 与服务端授权保护写入；事务统一更新状态、审核人、数据库时间和审计。成功后刷新清单、详情与总览，记录离开待审核清单仍保留所选详情。保存成功但读取失败提示无需再次审核；冲突、超时或响应丢失先查看最新状态，不自动重放写入。四个开发账号选项只作为真实凭据填充器，不能替代后端授权。

总览环图和作业概要是全港查询结果的可视化表达，不新增业务事实，不使用彩虹色或比较基准不明的装饰数字。

## Do's and Don'ts

### Do:

- **Do** 对照用户五张参考图保留冰蓝磨砂、紧凑侧栏、深蓝操作和明亮详情层次。
- **Do** 使用数据库查询字段和独立的全港概况，保持申请时间、实际事件时间与 UTC+8 时区语义清楚。
- **Do** 让布局承担解释，保留必要字段、错误恢复和无障碍名称；素材来源与合成数据性质保存在文档和元数据。
- **Do** 仅在摘要或场景区域少量使用海浪边，表格和表单保持整齐边界。
- **Do** 保留可见键盘焦点、状态文字、局部横向滚动与移动端导航。
- **Do** 延续共用外框与主次栏比例，导航保留筛选和选中项，查询使用局部反馈并保留表格滚动位置。
- **Do** 将详情选择与清单查询分开，已提交关键词可见且可清除；候选与动态展示真实总量并可继续浏览。
- **Do** 让动态标题和控件固定，尊重阅读暂停、页面可见性及减少动态效果偏好。
- **Do** 在桌面、窄屏与参考尺寸保存有效截图后再评价视觉完成度。

### Don't:

- **Don't** 恢复白底列表或深色顶栏，或用通用风格建议抹掉用户指定的玻璃材质。
- **Don't** 复制海报大字、水印、社交账号，或把裁片冒充真实船舶照片。
- **Don't** 在业务界面添加 Demo、课程演示数据、本地演示、更新时间、船舶示意角标或重复的排序说明行。
- **Don't** 为凑版式捏造 AIS、地图、登录身份、通知、全港统计或未实现的操作。
- **Don't** 在三个主指标旁添加口径不同的绿色辅助计数或无比较基准的勾号数字，也不要用预约申请时间推算 AIS 航程。
- **Don't** 用构建成功、静态预览或局部修复结论声称逐像素还原和整站全面验收。
