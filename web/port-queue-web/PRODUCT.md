# PortQueue 前端产品范围

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

单港口业务人员查询预约与审核结果；课程中期答辩由开发者演示数据库成果。

## Product Purpose

围绕进港预约、锚地排队、泊位时间窗与实际事件形成可追溯的管理系统。阶段 2 完成预约查询与跨业务只读总览，写操作页面按后续阶段逐项接入。

## Capabilities and Constraints

已由本会话确认：Vue 3 + TypeScript + Vite，后端 .NET 8，SQL Server。首页“总览”通过独立 API 显示待审核预约、锚地在场、待靠泊计划和近期事件；“进港预约”负责真实候选搜索、关键词/状态筛选、分页和选中详情。总览五条摘要与完整清单独立保存，页面往返保留各自条件和选择；全局指标保持待审核预约、锚地在场、待靠泊计划三项，不受筛选影响，也不附加绿色辅助计数。候选每批六条，显示真实总量并提供加载更多与查看全部结果；选择候选、总览详情或港口动态只更新详情，首次进入清单显示全部记录，后续保留关键词、状态、页码与每页条数。主动查询、筛选、分页和重置/清除条件才改变清单，已提交关键词可见且可清除。查询期间保留原表格与滚动位置，完成后替换，失败清除对应的失效结果；清单与详情独立恢复，清单错误不能遮住成功的独立详情。港口动态按真实总量分页，每页 12 条，固定标题、可暂停滚动及翻页；手动操作或触摸后等待主动继续，悬停、聚焦、后台、离开总览及屏外时停止，减少动态效果偏好默认暂停。场景流程仅表达草稿、待审核、已批准、已完成的预约办理阶段，驳回/撤销中断，不推算 AIS 航程。覆盖加载/空/错误状态，时间显示 Asia/Shanghai。第三阶段本轮仅规划身份权限、登记、草稿编辑、提交和审核，不实现写功能。

## Brand Commitments

名称 PortQueue，中文业务术语。2026-11-07 用户明确要求对照提供的 TIDELINE 参考图重做全部现有界面：冰蓝磨砂玻璃、纵向导航、紧凑顶部工具栏、横向摘要、主次内容区、船舶图像和紧凑表格。参考图位于 `../../docs/design/reference/`；此方向替代之前的白底表格和深色顶栏。

## Evidence on Hand

database/10_seed_demo.sql 保留原五条流程样例；12_refresh_sample_labels.sql 整理其业务编号和名称并留审计；13_seed_port_scenarios.sql 增加 48 条不同时间与状态的持久化合成场景。当前开发库 53 条预约、42 条实际事件记录，数量由 API 查询数据库，不能硬编码为界面统计。阶段 1 数据库规则验收已完成；真实港口/AIS 数据和账号认证尚未接入，账号区如实显示“未登录”。

## Product Principles

查询结果来自数据库；失败不能回退 Mock。申请、计划与实际时间分清。阶段范围小、可验证。Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining. 界面保留必要业务字段、错误恢复及无障碍名称；合成数据性质和图片来源在文档说明，场景图不绑定某条船舶记录。后续页面延续冰蓝商务风格，少量海浪边只用于摘要/场景区域，表单和表格保持规整。
