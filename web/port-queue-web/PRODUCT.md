# PortQueue 前端产品范围

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

单港口内部工作台：船公司/代理提供申请资料，调度员代为登记和提交，审核员审批，记录员后续登记实际作业。中期由开发者演示数据库成果，没有船员自助门户。

## Product Purpose

围绕进港预约、锚地排队、泊位时间窗与实际事件形成可追溯的管理系统。阶段 2 完成预约查询与跨业务只读总览；阶段 3A 完成真实身份会话与权限基础，3B 完成完整申报详情和预约批准/驳回，3C 完成登记、草稿编辑和提交。阶段 3 按 3A 身份权限 → 3B 审核 → 3C 登记提交分批验收。

## Capabilities and Constraints

已由本会话确认：Vue 3 + TypeScript + Vite，后端 .NET 8，SQL Server。首页“总览”通过独立 API 显示全港概要，不请求预约清单。顶部保留待审核预约、锚地在场、待靠泊计划三项指标，不受预约筛选影响，也不附加绿色辅助计数。预约分布覆盖全部记录的六种状态；删除“作业分布”横条和三个切换项；“进港流程”居中呈现审核后按需等泊或直接安排泊位；沿线小船只解释方向，支持暂停，屏外、后台、离页和减少动画时停止。后续环节标记待接入，不冒充实时进度。总览使用明亮蓝、天蓝、深蓝层次；主图显示配置港口的名称、代码、国家和系统已登记的设施数量，不承载单船轮播、审核摘要或办理进度。主港为上海洋山深水港，SH-YS 为内部代码。主图四入口布局保留：预约可用，后三者显示未接入提示并返回原焦点；侧栏后续业务含查询统计均待接入。只有总览、预约两页，旧 hash 回到总览，后续通用列表/API 已撤下。预约分布页脚独立，内容决定面板最小高度，短窗口允许总览内部滚动。

“进港预约”负责真实候选搜索、关键词/状态筛选、分页和选中详情。状态入口为全部加六种状态，桌面直列、窄屏换行，不再设置重复的全状态下拉框。页面往返保留清单条件与选择，不因导航重复请求。候选每批六条，显示真实总量并提供加载更多与查看全部结果；选择候选或港口动态只更新详情，首次进入清单显示全部记录，后续保留关键词、状态、页码与每页条数。总览状态点击属于明确筛选入口：清除旧关键词并打开对应状态的完整清单，“查看全部预约”同时清除状态限制。主动查询、筛选、分页和重置/清除条件才改变清单，已提交关键词可见且可清除。查询期间保留原表格与滚动位置，完成后替换，失败清除对应的失效结果；清单与详情独立恢复，清单错误不能遮住成功的独立详情。

港口动态按真实总量分页，每页 12 条，固定标题、可暂停滚动及翻页；手动操作或触摸后等待主动继续，悬停、聚焦、后台、离开总览及屏外时停止，减少动态效果偏好默认暂停。覆盖加载/空/错误状态，时间显示 Asia/Shanghai；不推算 AIS 航程。

阶段 3A 已实现标准 Cookie 登录/退出、真实姓名和角色、防伪造令牌、登录限速、账号与角色启停复核、密码重置使旧会话失效，以及本机受控账号维护。账号区在 Development 且显式启用时提供四个真实专用账号选项，初始密码为 123456，选择时自动填入，个人账号仍按安全命令维护。权限由后端和数据库事务共同控制：ADMIN/REVIEWER 可审核，ADMIN/DISPATCHER 可登记、编辑草稿和提交，RECORDER 当前只读。只读查询继续匿名开放。

3C 使用预约页侧栏完成登记。船舶、上一港和下一港从真实 API 候选选择，候选每页 20 条；任意文本不等于有效引用。本次到访预计时间与申请时间分别维护，只在主动选择“沿用申请时间”时复制。保存草稿、编辑、提交由数据库过程维护事务和审计；只有草稿允许编辑，提交时申请到港必须在未来。重复创建请求使用原键核对，编辑/提交的未知结果先查询；并发版本冲突不覆盖其他修改。后续三个查询页已按用户要求撤下，进锚、调序、计划确认及作业登记均待中期后仔细设计。

3B 审核确认绑定预约主键、船名和编号，批准意见选填、驳回原因必填。完整申报资料读取成功且处于待审核时才允许操作；会话提供审核人，CSRF、后端授权及数据库事务共同维护状态、审核时间和审计。成功后刷新清单、详情与总览，记录离开筛选后保留所选详情；保存成功与刷新失败分开反馈，响应丢失先读取最新状态。办理进度仅属于所选预约，撤销终态不推断此前获批。

四个开发专用账号为 pq.admin、pq.dispatcher、pq.reviewer、pq.recorder。快捷选项仍通过后端密码验证；生产环境不提供选项并拒绝专用账号登录。输入、凭据、会话及连接故障分别反馈，个人密码不保存到浏览器存储。

## Product Principles

查询结果来自数据库；失败不能回退 Mock。申请、计划与实际时间分清。阶段范围小、可验证。审核成功与读取失败分开反馈，未知写入结果先读取再决定。Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining. 界面保留必要业务字段、错误恢复及无障碍名称；合成数据性质和图片来源在文档说明，场景图不绑定某条船舶记录。后续页面延续冰蓝商务风格，少量海浪边只用于摘要/场景区域，表单和表格保持规整。

本批后端及 SQL 集成 98 项、SQL 基线 59 项、浏览器回归 34 项通过。预约状态测试根据真实 API 总量断言，不假定用户没有新增记录。洋山迁移不改变 21 表/3 视图，也不改写预约、前后港引用或实际记录；设施数量是系统内登记量，主图是既有场景素材，均不作为真实港口完整规模或现场摄影证据。当前范围、端口控制和演示步骤见 `../../docs/stages/midterm-delivery-guide.md`。视觉结论以本轮独立 review 的实际范围为准。

2026-11-10 看板收口：总览每30秒重新读取数据库快照；本页登记/审核成功立即刷新，离页/后台停止轮询，返回只有过期才读取。轮询不抢占正在进行的读取，不重置港口动态页码，错误清除失效数字。当前预约可由调度员/管理员在页面新增；基础资料新增及后续业务页面仍不在中期范围。用户原有前后端服务不属于验收清理对象。

本轮最终构建及40项完整浏览器回归通过，三指标支持键盘/触摸按需展开定义，失败恢复和手动刷新均保留动态请求页码。最新证据见 `../../docs/reviews/2026-11-10-dashboard-final-review.md`；此前34项结果保留为中期范围收口时的历史记录。
