# PortQueue 前端产品范围

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

单港口业务人员查询预约与审核结果；课程中期答辩由开发者演示数据库成果。

## Product Purpose

围绕进港预约、锚地排队、泊位时间窗与实际事件形成可追溯的管理系统。阶段 2 完成预约查询与跨业务只读总览；阶段 3A 新增真实身份会话与权限基础，并将总览收敛为独立全港概要。阶段 3 按 3A 身份权限 → 3B 审核 → 3C 登记提交推进，每次完成一个可验收业务批次。

## Capabilities and Constraints

已由本会话确认：Vue 3 + TypeScript + Vite，后端 .NET 8，SQL Server。首页“总览”通过独立 API 显示全港概要，不请求预约清单。顶部保留待审核预约、锚地在场、待靠泊计划三项指标，不受预约筛选影响，也不附加绿色辅助计数。预约分布覆盖全部记录的六种状态；作业概要分别显示有效锚地队列的等待分配/已分配、当前泊位计划的草拟/执行中，以及累计进港/靠泊/离泊事件。场景图展示业务环节，不承载单船轮播、审核摘要或办理进度。

“进港预约”负责真实候选搜索、关键词/状态筛选、分页和选中详情。页面往返保留清单条件与选择，不因导航重复请求。候选每批六条，显示真实总量并提供加载更多与查看全部结果；选择候选或港口动态只更新详情，首次进入清单显示全部记录，后续保留关键词、状态、页码与每页条数。总览状态点击属于明确筛选入口：清除旧关键词并打开对应状态的完整清单，“查看全部预约”同时清除状态限制。主动查询、筛选、分页和重置/清除条件才改变清单，已提交关键词可见且可清除。查询期间保留原表格与滚动位置，完成后替换，失败清除对应的失效结果；清单与详情独立恢复，清单错误不能遮住成功的独立详情。

港口动态按真实总量分页，每页 12 条，固定标题、可暂停滚动及翻页；手动操作或触摸后等待主动继续，悬停、聚焦、后台、离开总览及屏外时停止，减少动态效果偏好默认暂停。覆盖加载/空/错误状态，时间显示 Asia/Shanghai；不推算 AIS 航程。

阶段 3A 已实现标准 Cookie 登录/退出、真实姓名和角色、防伪造令牌、登录限速、账号与角色启停复核、密码重置使旧会话失效，以及本机受控账号维护。账号区与原生登录对话框调用真实会话 API，窄屏展开导航后可登录；密码不保存到浏览器存储。权限由后端控制：ADMIN 可登记提交与审核，DISPATCHER 可登记提交，REVIEWER 可审核，RECORDER 不具备这两类权限。当前只读查询继续匿名开放；3B 审核与 3C 登记提交的写端点及按钮尚未开放，已有策略不等于业务写功能完成。

## Brand Commitments

## Evidence on Hand

database/10_seed_demo.sql 保留原五条流程样例；12_refresh_sample_labels.sql 整理其业务编号和名称并留审计；13_seed_port_scenarios.sql 增加 48 条不同时间与状态的持久化合成场景。当前开发库 53 条预约、42 条实际事件记录，数量由 API 查询数据库，不能硬编码为界面统计。阶段 1 数据库规则验收已完成；真实港口/AIS 数据尚未接入。

## Product Principles

查询结果来自数据库；失败不能回退 Mock。申请、计划与实际时间分清。阶段范围小、可验证。Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining. 界面保留必要业务字段、错误恢复及无障碍名称；合成数据性质和图片来源在文档说明，场景图不绑定某条船舶记录。后续页面延续冰蓝商务风格，少量海浪边只用于摘要/场景区域，表单和表格保持规整。
